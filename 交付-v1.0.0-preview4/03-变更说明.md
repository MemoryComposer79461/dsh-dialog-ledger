## 二、产品侧（本版最大变更）：K-16 双管（读全 + 丢得起）

**缺陷（re4 实测）**：re4 的 K-16 上半把"读不全"处理成"整批不落账、游标不推进"（防半轮落账），但事件批读重试阶梯是 3 次（64 KiB → 1 MiB → 4 MiB），**数学上永远够不到 8 MiB 上界** → 跨在 4–8 MiB 单帧上的轮次每 tick 都被截断、**3 tick `written=0/0/0`、`cursor=null`、`lost=0`**；>8 MiB 单帧同样整会话停摆（第 3 轮审计 W-05："比 re3 更差"）。

**修法（双管）**：

| 管 | 做什么 | 落点 |
|---|---|---|
| **上半（读全）** | 重试阶梯 **3 → 4 次**（`EVENT_READ_ATTEMPTS=4`，64 KiB → 1 MiB → 4 MiB → **8 MiB**），预算 = 轮次字节跨度 + 32 KiB 余量；**4–8 MiB 单帧现在完整入账** | `index.js:206、3207、3217-3257` |
| **下半（丢得起）** | 预算耗尽且单帧超上界时，用 `readTurnsFrom` 做**有界缺口探测**（`maxFrameBytes=8 MiB` → frames 判"可跳过超大帧"、不 halt、不解压）；缺口自动写 `<root>\ledger\.lost.jsonl`（k15 形状）；该轮**不入账、不进已闭合计数**；游标推进到缺口之后的帧边界；WARN 出声 | `index.js:3262-3310、3442-3446`；`lib/ledger.js:2054-…`（`writeLost`） |

**验收证据（红→绿，构建区原件）**：

- **改前（红）**：`K16-红-before-fix-20261115.log` —— 3 tick `written=0/0/0`、`cursor=null`、`lostRows=0`；夹具 C 单帧 5,233,450 B、夹具 D 单帧 8,394,098 B，`attemptBudgets=[65536,1048576,4194304]`、`ladderMax=4194304`。
- **改后（绿）**：`K16-part2-20261115.log` —— 5.24 MB 单帧 **`written=22`**（第 22 轮完整入账，游标 5,234,513）；8.4 MB 单帧 **`written=21`** + `.lost` **1 条** + 游标 **8,395,161** + **1 条 WARN**（原文含"结构化跳过 1 轮（22）""缺口已写 `<root>\ledger\.lost.jsonl`（k15 形状）""该轮不入账、不进已闭合计数"）。
- **回归锁**：`docs/自测-K16大帧停摆.mjs`（C `:317` = >4 MiB 必读全；D `:377` = >8 MiB 允许丢该轮但必须可见 + 游标前进），2/2 绿并入全量 → 全量 **628**（= re4 622 + 本版 6）。
- `📝` 红→绿日志是构建区原件（`<build-root>\evidence\`），写稿时未随包；随包证据以 `证据/` 实物为准。

## 三、F1：未闭合轮可见（零静默丢账 / 零静默报绿）

**缺陷**：插件对"只见 `turn/start`、没见 `turn/end`"的轮次不写 partial、不假绿（这是对的），但**只写 `<root>/ledger/.pending.jsonl`**，`reconcile()` 与 `gate` 都不看 pending → 实测 `gate: ok / knownGaps: []`、run-report 无 `openTurns`。结果是某会话某轮**永久终止**（DSH 不再写该文件）时，这一轮永远不入账，而面板说"一切正常"（第 3 轮审计 R1 静默丢账 / R2 静默报绿）。

**修法**：

- `lib/gate.js`：`GATE_VERSION 2 → 3`（`:39`）；新增**可枚举缺口**（`:148-164`）：`未闭合轮=<n>（源已静止 >2×interval，逐项见 run-report.openTurns）`。
- `index.js`：按源 `mtime` 距 now > `2×intervalSeconds` 判 stale（`:2999` 收集 `openTurnList`；`:4411` 传 `{staleOpenTurns}`；`:4475` 落 `run-report.openTurns`）。**活跃写入的进行中轮次不计入**（不误报）。

**验收证据（红→绿）**：

- 改前 `F1-红-before-fix-20261115.log`：A 组 `knownGaps=["缺周账=1"]`、`report.hasOpenTurns=false`、无 openTurns。
- 改后 `F1-绿-after-fix-20261115.log`：A 组 `knownGaps` 含「**未闭合轮=1（源已静止 >2×interval，逐项见 run-report.openTurns）**」、`report.openTurns=1`、`stale=true`；B 组（源 mtime 新鲜）`staleOpenTurns=0`、`knownGaps=[]`（**不误报**）。
- 回归锁 `docs/自测-F1未闭合轮可见.mjs`（A `:143` / B `:200`），2/2 绿。

## 四、F2：封板补记失败可重试、连败必报警

**缺陷**：封板补记只在本轮"刚写台账行"时尝试一次；写失败一次 → 该 code **永远既不在正册也不在补记册**，后续任何 tick 都不再重试，而 `reconcile` 仍 `ok`（第 3 轮审计 R2 静默丢账）。

**修法**：

- 失败补记进 `state.supplementPending`（持久化待办，`index.js:1792-1794`），**每 tick 幂等重放**（`:3888-4001`）；成功后出队。
- **连败 3 次** → `gaveUp=true` + WARN + gate 缺口 `补记待补=N`（`:4000`、`:4411`、`lib/gate.js:162-164`）；待办随 state 持久化（`:4220`），逐项进 `run-report.supplementPending`（`:4477`）。

**验收证据（`F2-20261115.log`）**：

- A 组（障碍消失）：`supplements=1 / bookExists=true / pendingLeft=0` —— 下一个 tick 补进补记册并出队。
- B 组（注入路径不可写）：attempts **1→2→3**、`gaveUp=true`、`gate.knownGaps` 含「补记待补=1（连续 3 次写失败已放弃自动重试，逐项见 run-report.supplementPending）」、`pendLast.lastError` 有值；不吞错、不假绿。
- 回归锁 `docs/自测-F2补记可重试.mjs`（A `:147` / B `:179`），2/2 绿。

## 五、F3：并发双写（R4）——只更正被证伪的注释（K-22，不改行为）

- **审计结论**：`lib/lock.js` 旧注释写"持锁期间一直开着 fd，而 Windows 上被打开的文件不能 rename，所以活着的持锁者无法被夺取，等于给僵死判定加了一道文件系统级保险"——实测**能 rename / unlink**（带 `FILE_SHARE_DELETE` 打开即可），该假设被**证伪**。
- **本轮改动（只改注释，不改行为）**：`lib/lock.js:29-42` 按事实改写——① 不存在文件系统级保险，抢锁安全完全取决于心跳判定（30s 心跳 / 3× 陈旧 / 连续两轮确认 / 夺取前 rename 留证）；② 残余风险照实写：持锁者若在**长同步段**（超大会话事件批读、周账全量重算等）里超过 3× 心跳未刷 `heartbeatAt`，另一实例可合法判僵死并夺取 → 短窗口双写；重复/冲突行会被 gate 的 `codeUnique / sidTurnUnique` 判成 `unknown`（不是 ok），届时可发现、可弥补；③ 修复方向排 1.1：fencing 下沉到每行 append 前 + 长同步段主动 `beat()` 或分片让出 + `.state.json` 写加 CAS。
- **运行约束（随包披露）**：**不要同时开两个 DSH 实例写同一个账库根**（`lib/lock.js:42`；`VERSION.json:109`、`../00-怎么用.md`「注意」）。
- **签字/基线**：K-26（frames/ledger）、K-28（index 编排）、K-29（collector）均在机主 2026-11-15 一次性签署范围（S-13/S-14/S-15）；基线随出包 `--force` 重生成，`内核边界检查` = **6/6 KERNEL PASS**。
