## 一、这一版是什么

1. **产品侧最大变更：K-16 双管（本版最大改动）**。上半：`index.js` 事件批读重试阶梯 **3 次 → 4 次**（64 KiB → 1 MiB → 4 MiB → **8 MiB**，`EVENT_READ_ATTEMPTS=4`），修掉"阶梯永远够不到 8 MiB 上界"的洞；**4–8 MiB 单帧现在完整入账**。下半：**>8 MiB 单帧不再永久停摆**——用 `readTurnsFrom` 做有界缺口探测（`maxFrameBytes=8 MiB`），frames 判"可跳过超大帧"、不 halt、不解压；缺口自动写 `<root>\ledger\.lost.jsonl`（k15 形状），该轮**不入账、不进已闭合计数**，游标推进到缺口之后的帧边界，WARN 出声。落点 `index.js:206、3217-3257、3262-3310、3442-3446`；回归锁 `docs/自测-K16大帧停摆.mjs:317、377`；红→绿见 02 §一 #11。
2. **F1 未闭合轮可见**：`lib/gate.js` `GATE_VERSION 2→3`，新增可枚举缺口 `未闭合轮=N（源已静止 >2×interval，逐项见 run-report.openTurns）`；`index.js` 收集 `openTurnList` 并落 `run-report.openTurns`；**活跃写入的进行中轮次不计入**（不许误报）。落点 `lib/gate.js:36-39、148-164`、`index.js:2999、4411、4475`；回归锁 `docs/自测-F1未闭合轮可见.mjs:143、200`；红→绿见 02 §一 #12。
3. **F2 封板补记可重试**：失败的补记进 `state.supplementPending`（持久化待办），**每 tick 幂等重放**；连败 3 次 → `gaveUp` + WARN + gate 缺口 `补记待补=N`；成功后出队。落点 `index.js:1792-1794、3888-4001、4220、4477`；回归锁 `docs/自测-F2补记可重试.mjs:147、179`；红→绿见 02 §一 #12。
4. **F3 并发双写（R4）：本轮不改行为**，只删 `lib/lock.js` 里被证伪的注释（原文"Windows 上被打开的文件不能 rename"→实测**能 rename/unlink**），并把残余风险与运行约束写实（`lib/lock.js:29-42`）：**不要同时开两个 DSH 实例写同一个账库根**；fencing 下沉 / 长同步段 `beat()` / `.state.json` CAS 排 1.1。内核基线已按既定流程 `--force` 重生成，`内核边界检查` = **6/6 KERNEL PASS**（02 §四）。签字：机主 2026-11-15 已同意（K-22，`VERSION.json:69`）。
5. **回滚物随包互绑**：`../回滚/怎么回滚.md` 重写；新增 `../回滚/回滚锚.txt`（脚本生成）与 `../回滚/演练-可执行性.mjs`；对 **preview2 终包**（`异机检测包-lite-v1.0.0-preview2-20261115.zip`）实跑 **13/13 PASS**（04 §四）。
