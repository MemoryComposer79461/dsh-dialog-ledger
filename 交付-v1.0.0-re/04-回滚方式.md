# 04 · 回滚方式 · `v1.0.0-re`（lite 线 · 两轮审计修复包 / 候选）

> 原则：**回滚的是代码，不是账。** 本版**没有数据格式变化**——台账行仍 `v:3`、数据总库布局（`lib/layout.js`）未动、原文/附件/周账/月账布局未动；`.index/` 是派生物、`.tick-metrics.jsonl` 是度量、月账/周账可重建。**所以回滚只需要换代码，账库一个字节都不用动。**
> 依据：`VERSION.json`（`builtFrom=lite-v0.9.5-snap`、`baselineTag=lite-v0.9.4`、`rollback=git reset --hard lite-v0.9.5-snap`）；tag/提交数字现场来自 `.git\refs\tags\lite-v1.0.0-re`（`e4e5009…`）与台账 #16（`c512010`）。**本版 A/B/C 演练已实跑**（§五），不是"步骤待填"。
> 回滚目标选择：**默认退回 `lite-v0.9.5-snap`**（本版开工点，VERSION.rollback）；要退回上一个正式版则用 `lite-v0.9.4`；万一本版包损坏，用目录快照逐字节复原。

## 二、三种回滚动作

```powershell
$git  = '<build-host>\_工作\tools\MinGit\cmd\git.exe'
$repo = '<build-host>\_工作\lite'
```

### ① `git reset --hard`：整树退回（默认动作，推荐）

```powershell
& $git -C $repo rev-parse HEAD                  # 记下当前 HEAD（本版应在 e4e5009 或其后）
& $git -C $repo status --short                  # 确认干净（交付-v1.0.0-re 为未跟踪）
& $git -C $repo reset --hard lite-v0.9.5-snap   # 退回本版开工前（VERSION.json.rollback）
& $git -C $repo rev-parse HEAD                  # 期望 49c52d4…
# …验完/修完后复位回本版：
& $git -C $repo reset --hard lite-v1.0.0-re     # 期望 e4e5009…
```

- 期望：`VERSION.json.version` 变 `0.9.5`、`type` 变 `snap`；`docs\复核器\`、包内 `证据\`、`docs\自测-审计修复-P0.mjs`、`docs\自测-C25聚合预算.mjs` 等**消失**；`MANIFEST.sha256` 回到 476 行；`cordis.patch.yml`/`package.json` 回到 0.9.5-snap 身份。
- 代价：丢弃**已跟踪文件**的未提交修改；不删未跟踪文件（`交付-v1.0.0-re/` 保留）。

### ② `git checkout <tag> -- .`：只取文件，不动分支指针

```powershell
& $git -C $repo checkout lite-v0.9.5-snap -- .
& $git -C $repo status --short                  # 出现大量 " M"（文件被 0.9.5 内容覆盖）
& $git -C $repo checkout HEAD -- .              # 还原
```

- 用途：只想拿回某个文件/目录时的轻量动作；**注意**：`checkout -- .` 不会删除新版本多出来的文件（如 `docs\复核器\` 会以"死文件"存在），也不会恢复被删文件；HEAD 不变。

### ③ 目录快照恢复（不走 git，最接近"逐字节复原"）

```powershell
# 默认在副本目录里恢复、校验，不碰工作仓库：
robocopy "<build-host>\_工作\snapshots\v0.9.5-snap\tree" `
         "D:\restore-v0.9.5-snap" /MIR /NFL /NDL
# 再按 snapshots\v0.9.5-snap\manifest.sha256 逐文件校验：missing=0 changed=0 extra=0
```

- 用途：git 历史/工作树损坏时的兜底；素材 `v0.9.5-snap\tree`（477 / 7,790,393 B）本机在。**不推荐**直接 `/MIR` 覆盖工作仓库（会把 `.git` 一起覆盖，需先移出 `.git` 与交付目录）。

## 三、数据回滚口径

### 3.1 一句话

**回滚 = 换代码，账库不动。** 本版没有数据格式变化，旧代码读新代码写下的账库是安全的；反之亦然（生成器/索引/度量均可重建）。

### 3.2 逐对象

| 对象 | 回滚时怎么处理 | 说明 |
|---|---|---|
| `ledger\*.jsonl`（台账） | **不动** | 行格式 `v:3` 未变；K-4 改变的是"坏帧怎么消费"，不是行格式 |
| 完整原文 / 附件（`YYYY年MM月\`） | **不动** | 布局未变 |
| `.index\`（索引） | 可留可删 | 派生件；0.9.5 起的索引格式本版未改；不确定就删，下次 tick 按 stat 重建 |
| `.tick-metrics.jsonl`（度量） | 可留可删 | 只读度量；旧版不读新增字段，留着只是多几行数据 |
| 周账 `.xlsx` / 月账 `.md` | **不动** | 派生视图，指纹不变则不重写；旧代码能读 |
| `.state.json` / `.lost.jsonl` / `.pending.jsonl` | **不动** | 本版未改这些文件的格式；K-4 只改语义与写入时机 |
| 备份目录 | **不动** | `tools\backup.mjs` 产出的增量备份与版本无关 |

### 3.3 为什么"换代码就够"（四条硬理由）

1. **格式没变**：台账 `v:3`、布局、原文编码、索引分片规则都与 0.9.5-snap 相同；
2. **修复是"行为/性能"层**：K-4 坏帧语义、K-5 封板写侧、C25 预算、doctor 宽限都是行为或性能，不是格式；
3. **派生件可重建**：索引/度量/视图删了能重建，不承载账务事实；
4. **回滚不抹证据**：台账 append-only、tag 保留（见 §六）。

### 3.4 回滚后三个"不算问题"的现象

1. **旧版不认识本版新增的派生文件**：`证据\`、`docs\复核器\`、新增自测都是附加文件，不影响 tick；回滚后它们仍在（未跟踪/已跟踪视 tag 而定），属无害残留。
2. **索引可能短暂滞后**：若回滚前本版刚写过索引、回滚后旧代码按 stat 检测不一致 → 会重建/告警，属预期。
3. **`.tick-metrics.jsonl` 行数多几行**：度量只增不减，旧代码照常读已有字段。

## 六、回滚不是"抹掉证据"

- **版本台账 append-only**：回滚后**不要删行**；要更正就追加更正行（台账红线）。#16 行保留。
- **tag 保留**：`lite-v1.0.0-re`、`lite-v0.9.5-snap`、`lite-v0.9.4` 都是"这个版本存在过"的证据，**不要删**。
- **交付目录保留**：`交付-v1.0.0-re/` 是未跟踪新增，`reset --hard` 不会删它；回滚后仍可引用。
- **证据不重写**：回滚后再跑出的数字是新口径，不要覆盖/改写既有日志（`_工作\证据\` 只增）。
