# 03 · 变更说明 · `v1.0.0-re`（lite 线 · 两轮审计修复包 / 候选）

> 变更对象：`lite-v0.9.5-snap`（`fbb6f95`）→ **`lite-v1.0.0-re`**（tag `e4e5009`；代码提交 `c512010`）
> 一句话：**本版不是新功能版，是两轮审计（P0/P1）的修复包**——内核 K-4 坏帧 P0、K-5 封板写侧、M-01/M-02 数据与身份、C25 聚合预算、打包/doctor/收据锚/证据链；**判据 38 绿（C17 工具待重定、C38 待出包复跑）**，测试 560/518/42（0 新增失败）。
> 依据：`VERSION.json.auditFixes` / `kernel` / `tests` 原文，以及 `_工作\证据-K4\`、包内 `证据\`。

## 一、这一版是什么

1. **修复包**：从 `lite-v0.9.5-snap` 出发，按两轮审计清单逐条修；产品代码改动集中在 `lib/frames.js`、`lib/ledger.js`、`index.js`（K-4 坏帧语义）、`lib/sealjournal.js`（K-5 封板写侧）、`lib/receipt.js`（DEF-03 收据锚）、`tools/doctor.mjs`（ACPT-01 宽限）。
2. **身份/打包面**：`package.json`/`cordis.patch.yml`/`README.md` 身份统一（0.9.5；出包 bump 到 1.0.0）、`README.md` 重写 220 行、`locale/*` 补 `meta.detail`、死配置标 legacy、配置三方对齐（27 输入 / 21 显式 / 6 兜底）。
3. **证据链（EVID-01）**：包内新增 `证据\`（可复现清单 + 小样，21 文件 / 79,230 B）与 `docs\复核器\`（独立复核器，不 import 插件）。
4. **判定**：产品侧 40 条判据 **38 绿 / C17 RED / C38 NA**（C39 出包前已由 MANIFEST 重生成转绿）；测试 **560 / 518 / 42 / 0**（+13 新增自测全绿、2 条收据锚转绿、**0 新增失败**）；全量语料 **1,558 行 / 唯一 / 0 坏行 / 日期段违反 0**。
5. **不是最终 v1.0**：真实账库、跨机三台设备、第三轮审计都没有做（05）。本版是**候选**。

## 四、兼容性

### 4.1 产品侧（兼容，无数据格式变化）

- **台账行格式**：`v:3` 不变；总库布局（`lib/layout.js`）不变；原文/附件/周账/月账布局不变。
- **配置**：三方对齐（27 输入 / 21 显式 / 6 兜底），**未新增必填键**；旧配置可继续用。
- **Agent 工具面**：仍 3 个工具；面板 7 路由不变。
- **零依赖**：不 `npm install`、不联网、不调模型。

### 4.2 行为变化（必须知道，不是"纯修复"）

1. **坏帧语义变化（K-4）**：遇到坏帧时，已解出的轮**照常入账**，游标**停在已提交前缀**，不再推进到 EOF；源修复后**自动续记**。依赖"坏帧即停、停了就不动"的旧习惯需要改。
2. **超大单帧不再 halt（P1-3）**：`>4 MiB` 单帧或结构完整超限帧 → **跳过并继续**，记 loss 原因 `oversized-frame`；以前会 halt 整条链。
3. **封板写侧 O(1)（K-5）**：结果相同，但写盘量/耗时剧降（50 MB 册 52.43 MB → 655 B）。
4. **身份号**：包身份统一 0.9.5，出包 bump 1.0.0（**交付包导出的 `package.json.version` 与 VERSION 不同源**，lite 线版本以 `VERSION.json` 为准）。

### 4.3 不兼容点（仅验具/流程/元数据面）

- `MANIFEST.sha256` 行数 **476 → 528**（新增 复核器/证据/自测/交付相关），C39 必须在重生成后才能引用；
- 判据 `docs\判据-1.0.mjs` 的 C17 变异预期**需按 K-4 重定**（工具侧，不是产品）；
- 包内新增 `证据\`、`docs\复核器\` 目录（交付五件之外的新增，见 00 §三）。
