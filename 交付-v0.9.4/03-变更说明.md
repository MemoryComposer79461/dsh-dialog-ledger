## 一、这一版是什么

一句话：**0.9.4 是 0.9.3 之后的"P3 扩容版"**——先把 P3 三块能力做进 `0.9.4-snap`（**索引外部层** `tools/pointerindex.mjs`＋`tools/cli.mjs`、**周账滚动 W1–W5＋月账视图**、**备份工具 `tools/backup.mjs`**、**总目录容量告警 budget**），再用 `0.9.4-re1` 把三块**接进 tick**（`index.js` 接 `runWeeklyBudget`/月账/`syncIndex`、`stat` 新字段、journal 尾读缓存；`pointerindex.syncIndex` 把 C28 读放大 **12.8×→1.00×**；`doctor` ④ 按 S-10⑤ 拆口径；新增 `docs\判据-0.9.4.mjs` 与 `docs\工具-设备自检.mjs`）。

**成果（数字与口径见 02）**：C24＋C26–C37 **13/13 绿**（RED=0/NA=0/SKIP=0）；C28 由红转绿、C31 由 NA 转绿；doctor ④ 由 red（3.49×>1.25×）→ ok（r1 报告项/r2 1.1199/r3 0.03277）；测试 **532/488/44 → 547/503/44（新增 43 条自测全绿，0 新增失败）**；E3 只读索引 37 分片/1,338 行/145,287 B（**11.81%**）。

明确不做的事（逐条写清）：

1. **不新增配置键**：仍是 **21 键**，`cordis.patch.yml` 与 0.9.3 **逐字节相同**（`scanBudgetMs` 仍是 30000，不再改值）；W1–W5/索引/月账的预算都用**代码常量**（§二/§三）。
2. **不改台账行格式**（仍 `v:3`）、**不改数据总库布局**（`lib/layout.js` 未动）、**不改包名 / 导出入口 / Agent 工具面**（仍 3 个工具）。
3. **不迁移旧账库**（`legacy-marks` 仍冻结；不提供旧库升级路径）。
4. **不裁 `docs/`**：`docs/` 仍占代码树约 **七成七**（见 00 §三），本版只加不减（新增 7 个 docs）。
5. **不碰 KERNEL**：`lib/ledger.js`/`frames`/`sealjournal`/`pending`/`lock`/`week` 六个 KERNEL 文件**一字节未动**，内核默认基线 PASS（受控变更仍是 0.9.3 的 3 个：`weekly`/`original`/`reconcile`）；K-3（`readAll` 热窗）留 0.9.5。
6. **不做真实账库 / 跨机 / 三年合成库**：证据在 c01 小库、E3 只读库、三层合成夹具上（02 §七、05）。

1. **`readSealJournalState()` 的 `events` 改为摘要（无 `rows`）**：W5 为控内存把每个事件的 `rows` 数组剥掉，只留 `rowCount/rowsSha256/…`。若外部（或旧插件内代码）直接读 `events[i].rows`，会拿不到逐行快照——要看逐行 rows 请用 `lib/sealjournal.js: readSealEvents()`（KERNEL 只读接口）。这是**接口语义变化**，不是格式变化；本仓库内调用方已同步（`index.js`/`reconcile` 不依赖 rows）。
2. **索引目录 `ledger/.index/`**：账库 `ledger/` 下新增隐藏目录（分片 `idx-*.jsonl`＋`.idx-state.json`）。它**不是台账**（台账枚举/`readAll`/指纹都不把它当账行），但：① 账库目录里多一个目录；② 做"目录全量比对/备份"时会看到它变（`tools\backup.mjs` **默认跳过**）；③ 删掉可重建（C29 实测），旧代码（0.9.3/snap）不读它、可留可删。
3. **`MM月账.md` 新产物**：`<root>/YYYY年MM月/MM月账.md`。派生视图（可重建、不改台账/周账/journal）；但月份目录里多一个 md，总目录/容量统计/备份会看到它变；月末＋3 天冻结、指纹不变不写。
4. **`stat` / `.tick-metrics` 字段新增**：`stat` 新增 `weeklyDeferred/monthly/index`；`.tick-metrics.jsonl` 增 `weeklyDeferred`＋`monthly{…}`＋`index{built,rows,ms}`；`state.json` 增 `weeklyCatchup`（预算余量）。字段**只加不改**、旧读法忽略未知键；但若有人按"字段集严格相等"做断言/对账，会看到新字段。另：`.run-report` **没有** `weeklyDeferred` 专用字段（经 `warnings[]` 上报，05 #5）。

- **每周账滚动会改变读盘节奏**：稳态 journal 不再整读（W1）、封板组不再读 xlsx 文件头（W2）、bootstrap 按预算分批（W3）——"每 tick 读多少盘"的旧经验值不再适用；`stat.weeklyDeferred`＞0 表示本轮有组没处理完（下一 tick 续，别当"丢账"）。
