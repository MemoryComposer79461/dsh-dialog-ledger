## 一、这一版是什么

一句话：**0.9.3 是 0.9.2 之后的"稳产版"**——先把 P2 稳产核心做进 `0.9.3-snap`（K-2 `windowBytes` 透传、`index.js` 链式有界批读、热窗口给未完成游标开口、尾 4 KiB 指纹、tick 28 s/17 MiB 预算、单会话异常隔离/退避、分阶段计时、新增 `.tick-metrics.jsonl`、新增 C19 tick 外日检），再用 `0.9.3-re1` 修掉三处读放大（weekly 可证缓存 / original 抽样自检 / reconcile 增量）。**成果**：38.82 MB 大语料从 0.9.2 的"48/1,338 轮 + 永久停滞"变成 **3 个 tick 入账 1,338 行（0 重复 / 0 缺失）**，总读盘同口径 **−36.6%～−58.5%**。

明确不做的事（逐条写清）：

1. **不新增配置键**：仍是 **21 键**；`scanBudgetMs` 是**同键改默认值**（3000 → 30000），键集合不变（§六）。
2. **不改台账行格式**（仍 `v:3`）、**不改数据总库布局**（`lib/layout.js` 未动）、**不改包名 / 导出入口 / Agent 工具面**（仍 3 个工具）。
3. **不迁移旧账库**（`legacy-marks` 仍冻结；不提供旧库升级路径）。
4. **不裁 `docs/`**：`docs/` 仍占代码树约 **79.7%**（见 00 §三），本版只加不减。
5. **不做真实账库 / 跨机 / 17 会话全量**：本版证据全部在小库 lab ＋ E3 单会话大语料上（见 02 §七、05）。
6. **re1 不再新增内核改动**：唯一的 KERNEL 改动（K-2）已在 `-snap` 落地并签字，re1 只碰 3 个受控文件（`lib/weekly.js` / `lib/original.js` / `lib/reconcile.js`）。

### 2.1 K-2：`lib/ledger.js` 三处 `windowBytes` 透传（已签）

### 2.2 `index.js` 链式有界批读（P2-1）

| 项 | 内容 |
|---|---|
| 每批只读本批跨度 | 事件批读起点 = `max(链式起点 chainFrom, 本批首轮 startByte)`，**批间不回头**；上界 = 本批帧跨度 + 一帧余量（≤ `EVENT_READ_MAX_BYTES` = 8 MiB），窗口粒度 `EVENT_READ_WINDOW_BYTES` = 16 KiB、余量 32 KiB |
| 读全校验 | 本批 `turnSet` 必须**全部集齐**才返回；缺 → 预算 ×4 重试（`EVENT_READ_ATTEMPTS=3`，只在本批轮次没集齐时发生，不静默） |
| 短读不落账 | 重试后仍缺 → 调用方判"本批不落账"、游标不推进（`eventShortBatch`，必须为 0）；短读必须留痕 |
| 解决什么 | 0.9.2 的 E3 停滞：预算截断后游标停在巨帧起点（`offset=187`），下一轮又从 187 重读同一巨帧 → 永久停滞 + 每轮重复读。链式起点 + 整批提交让游标**只在本批全部落账后前移** |
| 体量 | `index.js` 131,649 B / 2,514 行 → **166,249 B / 3,082 行**（+34,600 B / +568 行，含预算、指纹、退避、度量、日检接线等全部 P2 改动） |

### 2.3 热窗口给"未完成游标"开口（P2-2）

- 旧逻辑按 `hotWindowSeconds` 过滤"最近没变过"的会话；但**上一轮没读完的游标**（`offset < size` 或 `partialCommit=true`）即使文件不再变，也必须继续读，否则永远补不上。
- 现在这类会话被**豁免热窗口过滤**（`.tick-metrics` 的 `hotWindowExempted` 计数），并且新增停滞检测：上一轮未完成、这一轮"既没进也没前进"的会话计入 `stalledDetected` + 可按源定位的 `stalledList`（`{source, reason, offset, size}`），**修好后应恒 0**。
- E3 实测：tick 2 的 `hotWindowExempted=1`、`unfinishedCursors=1`；全 6 tick `stalledDetected=0`。

### 2.4 尾 4 KiB 指纹：身份判断从"三证"变"四证"（P2-3）

| 证据 | 说明 |
|---|---|
| ① 大小 | `size` 相同 |
| ② 头部指纹 | `headFingerprintBytes`（配置值 4096）取样 sha256，且**沿用上一轮取样长度**（追加不改前缀，避免误判重写） |
| ③ mtime | 内容真被重写，mtime 一定变（0.9.2 已有） |
| ④ **尾部指纹（本版新增）** | 尾 4 KiB 取样 sha256（`TAIL_FP_BYTES=4096`，不新增配置键）；只在 `size` 相同时读（size 变了已证明文件变过，再读白花 IO） |

- 补的盲区：**"尾被改 + mtime 被还原"**（三证全同也会漏）。
- 纪律：老游标没有 `tailSha` → 按"**不能证明没变**"处理（重读一次，幂等不重复入账）；**绝不**把"没有尾指纹"当"尾部相同"。
- 计数器：`tailFpBytes` / `tailRewrites` / `identityRewrites` / `mtimeRewrites`，进 `.tick-metrics`。

### 2.5 tick 预算：28 s 硬顶 + 17 MiB 源消费预算（S-9 口径）

| 常量 | 值 | 含义 |
|---|---:|---|
| `TICK_HARD_MS` | **28,000** | 单 tick 目标 ≤30 s，留 2 s 给 state/run-report/.tick-metrics 收尾；`scanBudgetMs` 只允许更小，**不允许超过硬顶** |
| `TICK_READ_BUDGET_BYTES` | **17,825,792**（17 MiB） | 单 tick 源消费上限（S-9：≤17 MiB 消费量/tick）；超了先收**已提交批**，剩下的下一 tick 续（幂等闸门保证不重复） |
| `SCAN_READ_WINDOW_BYTES` | 1 MiB | 扫描遍帧读窗口 |
| `EVENT_BATCH_TURNS_FLOOR` | 32 | 巨帧场景"自动缩批"设下限，避免同一巨帧被逐批重读（E3 实测 86 轮巨帧 1.86 MB 被读 10+ 次） |
| `RECONCILE_INTERVAL_MS` | 60 min | 对账 + 运行报告节流（沿用） |

- `budget` 每轮写进 `.tick-metrics`：`{scanBudgetMs, effectiveMs, hardMs, readBytes, saturated}`；本轮实测 `effectiveMs=28,000`、`hardMs=28,000`、`readBytes=17,825,792`、`saturated=false`，tick 1–3 耗时 7,228 / 7,581 / 2,727 ms（**均 < 28 s**）。

### 2.6 单会话异常隔离 / 退避（P2-5）

- `SESSION_FAIL_BACKOFF_AFTER=3`：同一会话**连续失败 3 次** → 进入退避；`SESSION_FAIL_BACKOFF_TICKS=10`：退避 10 个 tick（按 `intervalSeconds` 折算墙钟）。
- 新增计数 `quarantined`（本轮因退避跳过）/ `quarantineNew`（本轮新进入退避）；隔离原因用 `SESSION_QUARANTINED` 文案包装，**不改** `lib/ledger.js` 的错误枚举（`ERROR_KINDS` 里没有它，故不进 errors、只进 warnings）。
- 目的：一个坏会话不许拖垮整轮记账（旧行为是一处抛错整轮失败）。

### 2.7 分阶段计时（P2-6 的一半）

- `phases`：`scanMs` / `eventsMs` / `persistMs` / `weeklyMs` / `reconcileMs` / `reportMs` + `otherMs`（= 总耗时 − 已计阶段），每轮写入 `.tick-metrics`。
- E3 实测 tick 1 的 7,216 ms 中：**persist 4,651 ms（64.5%）**、events 965 ms、scan 686 ms、weekly 464 ms、reconcile 331 ms —— 这就是"读盘/耗时花在哪"的机读证据（C25 口径）。

**不兼容点（如实写，3 条）**：

1. **tick 每轮多写一个 `.tick-metrics.jsonl`**（`<root>/ledger/` 下，append-only，每 tick 一行 ≈0.5 KB；一年 60 s 一 tick ≈ 52 万行 ≈ 260 MB 量级）。它**不是台账格式变更**（`.` 开头，不参与台账枚举/指纹/行数），但：① 账库目录里多一个文件；② 有人做"目录全量比对/备份"时会看到它变；③ 磁盘占用会随运行时间线性增长，**本版不做轮转/清理**（保留策略留给 0.9.4 的 C23）。
2. **`scanBudgetMs` 默认值变为 30000**（原 3000）。依赖"3 秒收工"旧行为的自动化/提示词需要显式把该键配小；否则大语料单 tick 最多用 28 s（`min(配置, 28000)`）。
3. **tick 的读写节奏变了**（行为变化，不是接口变化）：大语料不再停滞，一轮内可能读 40–170 MiB（measure-tick 口径）、写 548–593 行；任何按"每轮最多 16 MiB/48 行"写死的容量估算需要更新。

**不算兼容问题、但必须知道的**：

- **K-2 改了 KERNEL（`lib/ledger.js`）**：已签，且 `v1.0-lite` 基线随之重生成；对 0.5.0 旧基线仍是"已签核改"的 2 changed。
- **核心数 21 → 22**：新增 `lib/tickmetrics.js` 进核心（S-8 的"lib 剩下即核心"口径）；写核心代码的人要看 `core-manifest.json`。
- **新增 `docs/工具-日检.mjs`**：属 docs，不进 tick、不影响装载。
