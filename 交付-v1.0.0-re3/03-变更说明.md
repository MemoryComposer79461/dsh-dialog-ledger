## 二、产品侧改动（P0 与 P1）

### P0（三份审计中最高级）

| ID | 缺陷 | 修法 | 落点 |
|---|---|---|---|
| **P0-1 卸载不静止**（③ ARCH-01） | `dispose` 只 abort+clearInterval 同步返回，tick 未 await → 卸载后旧实例仍写盘（注入延迟实测 5 s 内仍写 9 文件） | `dispose` 返回 Promise，等待 in-flight/shadow 收敛；中止只落 `.state` 提交点，派生段全跳过；实测"卸载 resolve 后 5 s 零写盘" | `index.js` |
| **P0-2 同进程锁双写**（③ ARCH-02） | 同进程幂等返回同一 handle → 两实例各写各的、互删锁 | K-12：幂等键 `(root, instanceId)` + fencing token + 被接管 `lost=true` + release 双归属校验；`apply()` 每实例生成 `mount-<uuid>` instanceId | `lib/lock.js` + `index.js` |
| **P0-3 legacy 解压炸弹**（③ CORE-02） | `lib/legacy.js` 路径无解压上限，4 KB → 128 MiB，**每 tick 在链路** | K-9：`probeHeadEx` 只读会话头/首帧（16 KiB 起按需、读硬顶 4 MiB、单帧 `maxOutputLength` 1 MiB）；`resolvePairPrefixes` 单 tick 累计解压预算（64 MiB 软 / 256 MiB 硬，超限显式 `skippedPairs`）；`summarizeFile/readPrefixEvents` 走 frames 同口径。实测炸弹 RSS +1.3 MiB（改前 +385 MiB） | `lib/legacy.js` |

### P1（按审计编号）

## 六、兼容性与行为变化（升级前必读）

1. **数据格式**：台账 `v:3`、目录布局、原文/附件/周账/月账格式不变；**日结摘要升到 v3**（`originalCount` 改当日口径；旧 v1/v2 只读兼容、自动补发 v3、旧文件不动）。
2. **行为变化**：
   - `enabled/weeklyEnabled/checkupEnabled` 严格布尔（`"false"` 字符串不再当开）；
   - 卸载会等待当前 tick 收敛（卸载可能比旧版慢，最长至 tick 硬顶，但不再"卸载后还写盘"）；
   - 面板守卫更严：非回环 Host / 跨源 / rebinding 形态一律 403；缺 Host 头也 403（fail-closed）；`/ping` 不再回显绝对路径；
   - 超大帧不再让会话停摆（可跳过并留证）；坏帧游标可能停在更早位置（宁慢勿丢）；
   - `.lost.jsonl` 新增 `skippable/retryable/skippedRanges/nextSafeOffset` 等字段；
   - `.tick-metrics.jsonl` 新增真读字节/分段耗时/锁跳过/挂载等字段（additive）。
3. **回滚**：包内 `回滚\` 目录带上一版代码 zip + sha256 + 步骤；回滚只回代码、不动账库（详见 04）。
