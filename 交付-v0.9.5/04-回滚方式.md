# 04 · 回滚方式 · `v0.9.5`（lite 线 · 快照版）

> 原则：**回滚的是代码，不是账。** 本版**没有任何产品代码改动、没有数据格式变化、没有配置变化**（`git diff lite-v0.9.4 lite-v0.9.5-snap` 只有 4 个文件：`MANIFEST.sha256`、`VERSION.json`、`版本台账.md`、新增 `docs/判据-1.0.mjs`）——台账行格式仍 `v:3`、数据总库布局（`lib/layout.js`）未动、`cordis.patch.yml` 21 键逐字节不变、Agent 工具面仍 3 个、KERNEL 六文件一字节未动。**所以回滚只需要换代码，账库一个字节都不用动。**

> 依据：`VERSION.json`（`type=snap`、`baselineTag=lite-v0.9.4`、`rollback=git reset --hard lite-v0.9.4`）；tag/提交/快照数字均为写作时**现场实测**（MinGit 2.56.1 `rev-parse` / `ls-tree -r -l` / `_工作\snapshots\*\snapshot.json`，只读，未做任何 git 写操作）。

## 二、三种回滚动作

先设两个路径变量（下同；git 不在 PATH，用包外 MinGit）：

```powershell
$git  = '<build-host>\_工作\tools\MinGit\cmd\git.exe'
$repo = '<build-host>\_工作\lite'
```

### ① `git reset --hard`：整树退回（默认动作）

```powershell
& $git -C $repo rev-parse HEAD                  # 先记下当前 HEAD（本版应为 49c52d4…）
& $git -C $repo status --short                  # 先确认工作区干净（本版：空；交付-v0.9.5 为未跟踪）
& $git -C $repo reset --hard lite-v0.9.4        # 退回本版开工前（VERSION.json.rollback）
& $git -C $repo rev-parse HEAD                  # 期望 a304768…
& $git -C $repo reset --hard lite-v0.9.5-snap   # 复位回本版（HEAD 回 49c52d4）
```

- 期望：HEAD 从 `49c52d4` 变为 `a304768`；`VERSION.json.type` 变 `formal`、`version` 变 `0.9.4`；`docs\判据-1.0.mjs` **消失**；`cordis.patch.yml` **仍是 `scanBudgetMs: 30000`**（21 键逐字节相同）；`git status --short` 只剩未跟踪的 `交付-v0.9.5/`（未跟踪文件不会被 `--hard` 删除）。
- 代价：丢弃**已跟踪文件**的未提交修改；不删除未跟踪文件（`交付-v0.9.1/`～`交付-v0.9.4/` 是已跟踪目录，`--hard` 会把它们恢复成目标版本中的样子；`交付-v0.9.5/` 不在任何旧 tag 里，属未跟踪，保留）。
- 本仓库 `core.autocrlf=false`（现场 `git config --get` = `false`；MinGit 2.56.1），复位**不做换行转换**，工作区字节与提交一致。
- 退回 `lite-v0.9.5-snap`（本版开工点）：`& $git -C $repo reset --hard lite-v0.9.5-snap`（HEAD 变 `49c52d4`；`VERSION.json.version=0.9.5`、`type=snap`；`docs\判据-1.0.mjs` 回来）。
- 退回 0.9.3 正式版：`& $git -C $repo reset --hard lite-v0.9.3`（HEAD 变 `413f184`；测试基线回到 504/460/44；**40 条判据入口/0.9.4 判据执行器/设备自检从代码里消失**，只剩 `判据-0.9.1.mjs`）。
- 退回 0.9.2 正式版：`& $git -C $repo reset --hard lite-v0.9.2`（HEAD 变 `71f259c`；`scanBudgetMs` 回到 **3000**）。

### ② `git checkout <tag> -- .`：只取文件，不动分支指针

```powershell
& $git -C $repo checkout lite-v0.9.4 -- .
# 或只退单个文件（例：只把 VERSION.json 与台账退回 0.9.4，保留判据执行器——不推荐，见注意）
& $git -C $repo checkout lite-v0.9.4 -- VERSION.json 版本台账.md
```

- 期望：工作区文件变成目标 tag 内容，HEAD 不变，`git status` 显示一堆"已修改"——这是**故意**的，用于"只拿旧文件比对/临时跑一下"。
- 注意：`checkout -- .` **不会删除**目标 tag 里不存在的文件（`docs\判据-1.0.mjs` 在 0.9.4 里不存在，会留在盘上；此时 `VERSION.json` 是 0.9.4 而判据执行器仍在，属"混搭状态"——**只用于比对，不要在这个状态出包**）。要干净复原请用 ①。
- 想恢复成 HEAD：`& $git -C $repo checkout HEAD -- .`。

### ③ 目录快照恢复（不走 git；最接近"逐字节复原"）

**前提（重要）**：快照树里**没有 `.git`**（`_工作\tools\snapshot.mjs` 的 `copyDir` 跳过 `.git`），`snapshots\v0.9.5-snap\tree` 是**整仓 477 文件 / 7,790,393 B**（含 `交付-v0.9.1/`～`交付-v0.9.4/`、`MANIFEST.sha256`、`docs\判据-1.0.mjs`），**不含本版 `交付-v0.9.5/`**（快照早于交付五件）。所以：

**不要**直接把快照 `robocopy /MIR` 到 `_工作\lite` 根目录——`/MIR` 会**删掉 `.git`**（仓库历史和 tag 全没），也会删掉本版 `交付-v0.9.5/`。正确做法二选一：

```powershell
# 方案 A（推荐）：在副本目录里恢复与校验，不碰工作仓库
$snap = '<build-host>\_工作\snapshots\v0.9.5-snap\tree'
$dst  = '<build-host>\_工作\回滚演练B\v0.9.5-snap'   # 或任意空目录
robocopy $snap $dst /MIR /NFL /NDL /NJH /NJS

# 方案 B：原地恢复（先移出 .git 与交付-v0.9.5，再镜像，最后放回）
$lite = '<build-host>\_工作\lite'
Move-Item "$lite\.git"            '<build-host>\_工作\_tmp-git-暂存' -Force
Move-Item "$lite\交付-v0.9.5"     '<build-host>\_工作\_tmp-交付v095-暂存' -Force
robocopy $snap $lite /MIR /NFL /NDL /NJH /NJS
Move-Item '<build-host>\_工作\_tmp-git-暂存' "$lite\.git" -Force
Move-Item '<build-host>\_工作\_tmp-交付v095-暂存' "$lite\交付-v0.9.5" -Force
```

- 期望：恢复后按 `snapshots\v0.9.5-snap\snapshot.json` 核对 = **477 文件 / 7,790,393 B**；逐文件 sha256 与 `snapshots\v0.9.5-snap\manifest.sha256`（**49,236 B**）比对 **missing=0 / changed=0 / extra=0**（方案 A）；方案 B 放回交付目录后 `extra=5`（本版交付五件，属预期）。
- 注意：快照是 **0.9.5-snap 整树**（`MANIFEST.sha256` 已按 476 行/49,154 B 口径生成）；恢复后 `git status` 会全量"已修改"（工作区与 HEAD 不一致属预期）——**恢复后不要直接 commit**，先 `git reset --hard lite-v0.9.5-snap` 对齐，或只在副本目录里用快照。
- **0.9.4 也恢复得了**：把 `v0.9.5-snap` 换进命令即可（476 文件 / 7,679,836 B）；0.9.3/0.9.4-re1/0.9.4-snap 的快照也在。

## 三、数据回滚口径（★ 本版重点：无数据格式变化）

### 3.1 一句话

**本版没有任何数据层变化 → 代码回滚不用动账。** 0.9.4 的派生件（`.index/`、`MM月账.md`、`.tick-metrics.jsonl` 新键、`state.weeklyCatchup`）在 0.9.5 里**一个都没有新增/修改**；账库布局、行格式、配置、journal、周账、备份全部原样。

### 3.2 逐对象口径

| 对象 | 回滚时怎么处理 | 为什么 |

| `ledger/.seal-journal.jsonl` | **不动** | 本版未改 journal 写法/格式 |
| `ledger/.state.json` | **不动** | 本版未改 state 键；0.9.4 已有的 `weeklyCatchup` 键旧代码忽略 |

| 交付五件 `交付-v0.9.5/`、证据目录 | **不随 git 回滚消失** | 交付目录未跟踪；证据在 `_工作\证据\`（仓库外） |

### 3.3 回滚 = 换代码，四条硬理由

1. **产品代码零改动**：`git diff --name-status lite-v0.9.4 lite-v0.9.5-snap` 只有 `MANIFEST.sha256`/`VERSION.json`/`版本台账.md`（元数据）＋新增 `docs/判据-1.0.mjs`（验具）；`index.js`/`lib/`/`tools/`/`freeze/` 0 命中。
2. **台账行格式未变**：仍 `{"v":3, code, ts, sid, turn, seq, status, turnState, src, doc, …}`；KERNEL 六文件一字节未动（内核检查 `[PASS] exit 0`）。
3. **配置 21 键未变且逐字节相同**：不存在"代码与配置混搭"。
4. **数据总库布局未变**：`lib/layout.js` 未动；本版没有新增派生目录/文件（`.index/`、`MM月账.md` 都是 0.9.4 已有的）。

### 3.4 ★ 回滚必须知道的三个"不算问题"的问题

1. **代码回滚 ≠ 交付文档/证据回滚**：`交付-v0.9.5/` 与 `_工作\证据\判据-1.0-*` 不会因 `git reset --hard` 消失（未跟踪/仓库外）。回滚后如果你要"回到 0.9.4 的材料口径"，别把 0.9.5 的证据当 0.9.4 的证据用——**证据与版本必须成对引用**。
2. **`docs\判据-1.0.mjs` 的取证副作用**：它只写 `..\证据\判据-1.0-*\` 与 `..\lab-10c-work\`（默认删），不写账库；回滚到 0.9.4 后它不存在，若你手工保留了该文件，它也**不会**被产品代码调用（死文件），但会读包内 `交付-v0.9.4`/`VERSION.json`，**在混搭状态下跑出的 F 组结论无效**（判据对象变了，05 #6）。
3. **退到 v0.9.0 基座的"读语义差异"仍在**（沿 0.9.3/0.9.4 的口径）：本版 `ledger/.seal-journal.jsonl` 按 S-1 只写"封板事实"（`prevSealSha256` 恒 `''`），0.9.0 基座代码读本版写过的库会把缺链行按"链断/坏行"处理 → 门可能降级。**默认回滚目标 `lite-v0.9.4` / `lite-v0.9.5-snap` / `lite-v0.9.3` / `lite-v0.9.2` 都是同一口径，没有这个问题；退基座只用于"整包回看/比对"。**

## 五、回滚演练（步骤 + 预期；实际结果由 lead 填）

> 演练纪律：在 `_工作\lite` 内做（动作③ 用副本目录）；演练前先 `git status` 确认没有未提交的已跟踪改动；演练只碰代码，不碰账库（`_工作\c01-lab` 只读跑判据/自检，不写）。
> **说明**：本文件写作时**未做演练**；`_工作\snapshots\` 有 `v0.9.5-snap` 与 `v0.9.4` 等 6 份素材，所以 B 可对两者各做一次"恢复＋逐字节校验"。

### 5.1 演练 A · git 退回开工前再复位（默认路径）

## 六、回滚不是"抹掉证据"

- **版本台账 append-only**：回滚后**不要删行**；要更正就追加更正行（台账红线）。0.9.5-snap 的 #15 行与将来的 #16 行都要保留。
- **tag 保留**：`lite-v0.9.1`（`f932108`）/ `lite-v0.9.2` / `lite-v0.9.3` / `lite-v0.9.4-snap` / `lite-v0.9.4-re1` / **`lite-v0.9.4`** / **`lite-v0.9.5-snap`** 与将来的 `lite-v0.9.5` 都是"这个版本存在过"的证据，**不要删**。
- **目录快照保留**：`_工作\snapshots\v0.9.5-snap`（477 / 7,790,393）与 `v0.9.4`（476 / 7,679,836）、`v0.9.4-re1`（471 / 7,545,125）、`v0.9.4-snap`（467 / 7,271,120）、`v0.9.3`（461 / 6,982,189）、`v0.9.3-re1`（456 / 6,868,175）是逐字节复算的唯一依据，不要清。
- **证据保留**：`_工作\证据\判据-1.0-20261113-202818/`（40 条主跑）、`…-203131`（防伪复核重跑）、`…-202651`（proof 8/8）、`判据-1.0-防伪复核-20261113.log`、`判据-1.0-内存采样.log`、`判据-v0.9.1/`（28 份 C01–C18 日志）、`094-criteria-20261113-202915/` 与 `094-criteria-20261113-203228/`（C24/C26–C37）、`跑测试-095snap-20261113.log`；以及 0.9.3 的存档 `202818\0.9.3-沿用-判据-v0.9.1-存档\`（28 份）——都**不要删**。
- **回滚不是修复**：回滚解决"本版代码有问题"（本版其实没改产品代码），不解决"账库已经被写坏/没写全"；已入账的行不会因回滚消失，未入账的轮次旧代码也不会补；索引/月账是派生件，删了能重建、留着会滞后，都不是账务事实。
