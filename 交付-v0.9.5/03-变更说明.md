## 一、这一版是什么

一句话：**0.9.5 是 P4 验收机具版**——只新增一个判据执行器 `docs\判据-1.0.mjs`（**2,091 行 / 112,310 B**），把散在三个执行器里的 **40 条判据收成一个入口**（C01–C18 子进程复用 `判据-0.9.1.mjs`、C24＋C26–C37 子进程复用 `判据-0.9.4.mjs`、9 条缺口本地实现），实测 **40/40 GREEN、exit 0**、`--proof` **8/8 PASS**；**产品代码零改动**（`index.js` / `lib/` / `tools/` / `freeze/` / 其它 `docs/` 一字节未动，git 树只 4 个文件变化：`MANIFEST.sha256`、`VERSION.json`、`版本台账.md`、新增判据执行器），测试 **547/503/44 不变**。

**成果（数字与口径见 02）**：40 条一个执行器全绿（主跑与防伪复核重跑各一次）；8 条先红后绿；C01–C18 在 0.9.5 树上**现场重跑 18 绿**（0.9.4 的最大缺口"未复跑"由此关闭，但产品代码与 0.9.4 零差异，见 02 §2.1-1）；C24＋C26–C37 现场重跑 13 绿；测试 547/503/44 与 0.9.4 失败集合逐条相同（0 新增失败）。

**明确不做的事（逐条写清）**：

1. **不改产品代码**：`git diff --name-status lite-v0.9.4 lite-v0.9.5-snap` 只有 4 个文件（3 改 1 增），`lib/`、`index.js`、`tools/`、`freeze/`、`locale/`、`P0验收/`、其余 `docs/` **0 改动、0 删除**。
2. **不改判据原文**：40 条判据条款一个字未动；本版只补"执行器"（9 条缺口），并把三条已有执行器聚合。改判据属机主签字事项（台账红线 4）。
3. **不新增/不删除测试**：测试文件仍 45 个；`docs\判据-1.0.mjs` 是**验具**不是测试，不进 `跑测试.mjs` 清单。
4. **不裁 `docs/`**：P4 原计划裁 docs，**本版决定不裁**（理由见 §四）；`docs/` 仍占代码树 **78.28%**。
5. **不碰 KERNEL / 配置 / 台账格式 / 布局 / 工具面**：KERNEL 六文件与受控文件均未动；`cordis.patch.yml` 21 键逐字节不变；台账行仍 `v:3`；`lib/layout.js` 未动；Agent 工具仍 3 个；`package.json` 未动（`version` 仍 `0.9.0`，lite 线版本号以 `VERSION.json` 为准）。
6. **不出包、不做正式版**：本版是 `type=snap` 快照；MANIFEST 由 lead 出包最后一步重生成；`lite-v0.9.5` 正式 tag 与台账第 17 行（#16）由 lead 补（正版必须由同号 `-re` 升，台账红线 2）。
7. **不做真实账库 / 跨机 / 三年合成库 / 48 MB 语料**：证据在 c01 小库、E3 只读库、三层合成夹具上（02 §五、05）。

## 四、不裁 `docs/` 的决定与理由（本版关键决定）

**事实（脚本口径）**：`docs/`  **399 个文件 / 5,740,958 B**，占代码树 **78.28%**（分母 = 全包除 `MANIFEST` 与五套交付目录：**456 文件 / 7,334,074 B**）；0.9.4 是 398 / 5,628,648（77.94%）——本版 **+1 个文件**（即 `docs\判据-1.0.mjs`，112,310 B），其余 docs 一字节未动。

**P4 原计划**：裁 `docs/` 以减轻包体（审计阅读成本高、包大）。

**本版决定**：**不裁**。理由五条：

1. **40 条判据的 3 个执行器全在 `docs/`**：`判据-0.9.1.mjs`（10,703 B）、`判据-0.9.4.mjs`（97,443 B）、`判据-1.0.mjs`（112,310 B）。裁 docs＝把验收机具裁掉，40 条立刻不可复跑。
2. **C38 抽查的 8 个生成器全在 `docs/`**（跑测试/语料四数/判据/日检/…）；C39 校验的是全包逐文件哈希——裁 docs 会让 C38/C39 的"数字可追溯"断链。
3. **C01–C18 的断言与反证（C15/C16/C17 的注入器）是 docs 里的自测脚本**；0.9.3 的 28 份沿用日志/生成器也在 docs 路径下。裁掉＝P1 门不可复算。
4. **"数字脚本生成 / 未验≠通过"两条元规则要求证据可复算**：docs 是"判据可复算的证据与工具"，裁了会破坏 40 条可追溯性（这是本版最硬的理由）。
5. **包体不是本线当前约束**：真问题在到量后的内存/性能（K-3、C28 回退），不在 1–2 MB 的 docs；先裁 docs 属于"优化错方向"。

**代价（如实）**：包体大（docs 5.74 MB，占七成八）、审计阅读成本高；`05 #16` 登记，并写明"**何时可裁**：先定'交付证据 vs 过程资料'口径，不能拍脑袋删"。

**影响**：本版 `00-交付清单` 的 docs 占比/包体表按"未裁"口径给；任何对外材料不得声称"P4 已瘦身 docs"——**P4 瘦身没有发生，是决定不做**。
