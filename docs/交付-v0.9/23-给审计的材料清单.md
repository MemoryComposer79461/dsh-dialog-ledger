## 一、五分钟：先把包本身验一遍

```powershell
# ① 逐文件哈希（期望：不一致 0 个）
$root = (Resolve-Path .).Path
$bad = 0; $n = 0
[System.IO.File]::ReadAllLines((Join-Path $root 'MANIFEST.sha256'), [System.Text.Encoding]::UTF8) | ForEach-Object {
  $m = [regex]::Match($_, '^([0-9a-f]{64})  (.+)$'); if (-not $m.Success) { return }
  $n++
  $f = Join-Path $root $m.Groups[2].Value
  if (-not (Test-Path -LiteralPath $f)) { $bad++ }
  elseif ((Get-FileHash -LiteralPath $f -Algorithm SHA256).Hash.ToLower() -ne $m.Groups[1].Value) { $bad++ }
}
"校验完成：$n 个文件，不一致 $bad 个"
```

## 三、"账记得对"这条，请优先审

这是本项目唯一真正重要的判据。复核器（`08-复核器/复核.mjs`）的设计是**双实现**：

- 生产侧：插件 `index.js` + `lib/*`；
- 复核侧：`复核.mjs` **只用 Node 标准库**，自己切 zstd 帧、自己解压、自己配对、自己算见证，**不 import 插件任何模块**；
- 差异分 A（源有账无）/ B（账有源无）/ C（状态不符）/ D（内容见证不一致）/ E（复核不到）。**A/B/C/D 必须为 0**，E 允许但必须明列。

`SHA256SUMS` 里冻结了复核器代码三件套；本轮重跑前先校验这三个值未变（见 `08-复核器/SHA256SUMS-重基线说明-20261111.md`）。

## 五、我们明确做不到的（请不要按"应该做到"打分）

1. **不联网、不调模型、零依赖** —— 所以没有可信时间戳、没有第三方签名、没有 CA；
2. **单机单用户** —— Agent 工具面没有身份鉴权，任何本机调用方一视同仁；
3. **KERNEL 冻结** —— 采集/编码/封板的核心六文件本版逐字节未动，改它们等于换内核；
4. **账本 append-only** —— 已入账的行不会因为源文件后来被改而回写；这是账本语义；
5. **快照锚是"某一时刻"的记录** —— 对持续增长的活账本做逐字比对，必然显示差异，这是快照语义，不是校验失败。
