## 口径 1 · 周记账的内容从哪来 ✅ 已定

**结论：行永远来自台账（银行日记账）；原文只作附件校验与追溯，不参与行生成。**

| 项 | 结论 |
|---|---|
| 行生成 | 台账记录（`code`/`ts`/`turn`/`status`），一行不多一行不少 |
| 「原文」列 | 附件指针，四态：绑定 / 补记 / **已清理（RPT-…）** / 缺凭证 |
| 原文被清理 | 行**不消失**，标「已清理」——记账凭证永久 |
| 文档原句 | 改为："周记账内容由台账填写；原文作为附件校验与追溯。" |

**理由**：字面实现"由原文填写"会让"原文清理 → 行消失"，直接违反"记账凭证永久"。

## 口径 2 · 交接表「删了不重建」怎么实现 ✅ 已定（C 方案）

**结论：封板状态落 `.state.json`（`handoverSealed`），同时把封板信息写进文件头。**

| 情形 | 行为 |
|---|---|
| 从没生成 | `generate`：生成主表 + 附表 → 记录封板 |
| 文件在、但没封板（旧版/手工放入） | `adopt`：**只补封板记录，不重写文件**（"只生成一次"包含"认它"） |
| 已封板 | `skip`：无论文件在不在，都不再生成 |
| 封板后文件被删 | 仍 `skip`（状态在 state） |
| state 一起丢（整库删除/换机） | 视为"重新开账"，允许重建 |

**理由**：只看文件存在性无法区分"从没生成"与"生成后被删"。封板记录放在与台账同机的 state 里，
文件头里的封板块保证"可搬、可人读"。

**代价（写明）**：state 与数据总库同生共死；换机时若只搬文件不搬 state，交接表会重建一次。
