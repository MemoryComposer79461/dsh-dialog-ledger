# V0.7 · 采集层换轨设计（草案 v0.1）

> 状态：**设计草案**（2026-11-10 晚）。事实依据待 `_V07采集API调研.md` 回填；本草案先定**不变量、接口、影子双轨与切换/回退纪律**，实现只做"可回退的最小换轨"。
> 纪律：KERNEL（`lib/{ledger,frames,sealjournal,pending,lock,week}.js`）**不动**；本版只新增采集适配层与开关，不重写落账/封板/周账。

## 一、现状（v0.6.4）

- 采集入口：`index.js runOnceCore()`（每 `intervalSeconds` 秒一轮，单实例锁内）→
  `lib/legacy.js scanSessionSources(<DSH_HOME>/sessions)` 扫描会话文件 → `lib/frames.js` 逐帧解码
  → 提取"已闭合轮次" → KERNEL 落账（append-only `ledger/YYYY-MM-DD.jsonl`，行 `v:3`）。
- 增量游标：按文件字节偏移（`fromByte`）+ 坏帧不推进（P1-5）；轮次去重靠 ledger 已存键。
- 优点：零依赖、可离线复核、磁盘即真相；缺点：①轮询有延迟（默认 60s）②必须读文件、跨进程/权限
  依赖文件布局 ③无法直接拿到宿主的"轮次闭合事件"，某些边界（文件被并发写/截断）只能靠兜底逻辑。

## 二、目标与硬不变量（换轨不得破坏）

| # | 不变量 |
|---|---|
| I1 | **账本只追加、不改写**；同一轮不得双记（幂等），不得漏记（有兜底）。 |
| I2 | 每行仍可**独立复核**：`v:3` 字段、编码、原文 hash、附件/视图口径不变。 |
| I3 | 采集来源可追溯：行内/运行报告记录"本轮由哪个采集器产生（disk/event）+ revision/seq"。 |
| I4 | **任何采集器异常不得拖垮记账**：捕获→降级→下一轮重试；不得让 fiber 崩（A13/A12 教训）。 |
| I5 | **可回退**：一个配置开关从 event 回 disk，行为与 v0.6.4 等价；不迁移/不改历史文件。 |
| I6 | **影子双轨不写账**：影子输出只进运行区（`.layout-shadow/` 或 `.state.json` 旁证），不改 ledger/原文/周账。 |
| I7 | 切换判据**先证后切**：影子期达到阈值（见 §六）才允许 `mode=event`；未达标保持 disk。 |

## 三、接口（新增，不侵入 KERNEL）

新增 `lib/collector.js`（纯函数式适配层，零依赖）：

```js
/**
 * @typedef {{ sid: string, source: 'disk'|'event', revision: number|null, path: string|null }} SessionRef
 * @typedef {{ sid, seq, role, at, text, attachments, closedAt, fingerprint }} Turn
 * @typedef {{ turns: Turn[], nextCursor: object, revision: number|null, warnings: string[] }} Batch
 */

createDiskCollector({ sessionsBase })  // 包装现有 scanSessionSources + frames 解码（行为 = v0.6.4）
createEventCollector({ host })         // 包装宿主 session/event 通道（调研后定 API）
collectTurns(collector, sessionRef, cursor) -> Batch
```

- `fingerprint` = `sha256(sid|seq|role|at|text)`（不含文件路径），用于双轨比对与幂等。
- 游标：disk 用 `{offset, size}`（沿用）；event 用 `{revision, seq}`（若宿主支持）。
- 兼容：`mode=disk` 时 event collector 完全不实例化（零风险回退）。

## 四、三阶段推进（先影子、再切换）

### 阶段 0：基线（v0.6.4，已具备）
现有 disk 采集 + 全量测试/复核/变异；作为对照基线。

### 阶段 1：影子双轨（v0.7.0，默认 `ingest.mode='shadow'`）
- 每轮 tick：disk collector 照常落账；event collector **只读**跑影子，输出：
  - `<root>/ledger/.shadow/YYYY-MM-DD.jsonl`：每会话 `{sid, revision, diskTurns, eventTurns, same, diffs:[...]}`；
  - `.state.json` 增 `shadow:{lastRunAt, sessions, exactMatch, diffCount, eventErrors}`。
- **不写 ledger/原文/周账**（I6）；影子文件属运行区（不属于台账/原文/周账产物）。
- 差异分类：`missing-on-event` / `missing-on-disk` / `text-diff` / `time-diff` / `role-diff` / `seq-diff` / `attach-diff`。
- 影子失败（event API 不可用/版本不匹配）→ 记 `eventErrors`，**静默降级**（I4），连续 N 轮失败自动关影子（熔断）。

### 阶段 2：双写对账（v0.7.0-rc，`ingest.mode='shadow'` + 人工口令 `--promote`）
- 对"影子一致"的会话，event 结果只用于**对账断言**（不落账）；不一致会话继续 disk 兜底；
- 生成 `docs/验收-v0.7/双轨对账-<日期>.md`：逐会话一致率、差异明细、风险清单。

### 阶段 3：切换（v0.7.0 正式，默认仍 `disk`；灰度 `event` 由配置显式开启）
- `ingest.mode='event'` + `ingest.fallback='disk'`：event 为主，disk 兜底补齐（event 缺失的轮次用 disk 差集补）；
- 每行记录 `source=event` + revision/seq；运行报告 `ingest` 段记录来源分布；
- 一键回退：`ingest.mode='disk'` 立即恢复 v0.6.4 行为（无需迁移数据）。

## 五、revision / 幂等 / 对账算法（草案）

1. 以 `(sid, seq)` 为轮次主键；`seq` 必须来自会话事件（缺失则退化为 `(sid, turnIndex, at)` 并告警）。
2. 每轮 `closedAt` 后才采集（与现有"已闭合轮次"口径一致）；未闭合不写。
3. 幂等：ledger 已存在 `(sid, seq)` → 跳过并记 `dupSkipped`；disk 与 event 双源同轮 → 只写一次，`source` 取优先源。
4. 补齐：`missing = diskKeys - eventKeys`，逐条用 disk 数据落账（标 `source=disk-fallback`）并在运行报告计数。
5. 对账不通过（同会话连续 3 轮差异 > 0）→ 熔断：该会话强制走 disk，告警一次；`ingest.mode=event` 下也保证不丢。

### 9.2 接口（定稿）

```js
/**
 * @typedef {{ sid:string, sessionId:string, source:'disk'|'persistence'|'event',
 *             revision:string|null, lastSeq:number|null, path:string|null }} SessionRef
 * @typedef {{ turn:number, startMs:number, endMs:number, reason:string,
 *             startSeq:number|null, endSeq:number|null }} ClosedTurn
 * @typedef {{ turns:ClosedTurn[], nextCursor:{seq?:number, offset?:number},
 *             revision:string|null, warnings:string[], bootstrap:'done'|'needed' }} ClosedTurnBatch
 */
createDiskCollector({ sessionsBase })        // 已实现（v0.7 起）；行为 = v0.6.7
createPersistenceCollector({ host, batchLimit }) // 已实现：list + open('read').read(seq,n)
createEventCollector({ host })               // 待实现（阶段 C 之后）
```

- 错误码（全部降级不抛，I4）：`EVENT_UNAVAILABLE` / `PERSISTENCE_UNAVAILABLE` / `PERSISTENCE_NO_READ` / `NO_SESSION_ID` / `BOOTSTRAP_NEEDED` / `SEQ_GAP` / `REVISION_STALE`。
- 游标：`{seq}` 持久（可放 `state.sourceCursors`）；`{revision}` 只放内存做"相等=没变"对账（不可跨重启，V7 待验）。
- 行内字段（I3）：`source:'disk'|'persistence'|'event'|'disk-fallback'`、`revision`、`seq` —— 由 `appendTurn` 透传（`JSON.stringify` 原样序列化，KERNEL 不动；V12 外部核验工具兼容性待真机验）。

### 9.3 三态比对（已实现）

`compareTurnSets(sid, diskTurns, otherTurns, { now, pendingWindowMs })`：
- `missingOnEvent` / `mismatched` → 真差异；
- `pendingDurable`：另一源有、磁盘还没有，且该轮 `endMs > now - pendingWindowMs`（良性"事件领先未 flush"）；
- `missingOnDisk`：超出 pending 窗口 → 真差异（须解释/补齐）；
- 默认 `pendingWindowMs=0`（严格模式，兼容旧测试）；影子模式建议 120s（V5 待真机标定）。

### 9.7 真机探针结论回填（2026-11-10 20:47，见 02-persistence真机探针.md）

- ✅ **V1 已答**：`SessionHandle.read(offset,length)` 的 `offset` **就是 seq**（offset=0→seq 0,1；offset=1→seq 1,2；EOF 返回 `events:[]` 不抛）。
- ✅ **V2 已答**：`stat()/list()` 键 = `header/formatStatus/revision/sizeBytes/location`，**不含 eventCount**；`revision` 是复合令牌字符串（不可排序、跨重启待 V7），变化检测只能"相等=没变"；增量只能靠 seq 游标。
- ✅ 新增事实：`open('read')` 返回 `{eventState, events}`，`eventState` 为状态串（本机 `"shared-frozen"`）；句柄含 `read/close`；list 条目 id 可能在 `header.id`。
- ✅ 采集器已按真机形状收口：`header.id` 兜底、`eventState` 透传、无 seq → `SEQ_MISSING` 停止、不依赖 eventCount；测试 10/10（含真机形状、normalizeSid 与无-seq 防御）。
- 探针已移除（DEV ONLY，代码里 `grep probePersistence` 为空），`_dl-probe.flag` 已删。
- ⬜ 仍待：V3/V5/V6/V7/V8/V9/V10/V11/V12（切 persistence 前按需补齐）；影子报表与 R-02/R-04/R-07/R-08/R-10 守护。
