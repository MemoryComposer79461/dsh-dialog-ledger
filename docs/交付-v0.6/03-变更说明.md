## 二·B、rc.2 增量（D18 修正：反伪装 + 运行报告/面板曝光）

> 触发：机主 2026-11-10 签 D18（legacy 单列），但要求先补 A（反伪装用例）、B（运行报告/面板曝光）；C（gate 三级）延后 v0.6.1。

**A 暴露了一个真漏洞，所以是补设计而不只是补测试：** 实证探针显示，把一条 v0.5 台账行的 `docFileSha256/docSha256/attachment` 删掉后，reconcile 会把它归入 legacy、不计缺凭证——**"删字段就能洗白"**。

**修正设计：legacy 必须由"正面证据"确认，不能凭"没有证据"推断。**
- 新增 `<root>/ledger/.legacy-marks.jsonl`：append-only + 哈希链（`prevHash` 接上一条 `hash`），由一次性工具 `docs/工具-标记legacy基线.mjs` 显式写入。

  未标记的无证据行一律进 `originalMissing`（`reason:'NO_BINDING_EVIDENCE'`），指纹不符记 `mismatched`，链断记 `chainOk:false`。
- 工具三态：默认 dry-run（不写盘）、`--write`（幂等，冲突不覆盖）、`--check`（只校验链与现状）。

**B：让 legacy 口径可见（"不隐藏"）。**

- 面板健康度第一屏新增两项指标：「历史无证据」「未标记无证据」；
- 对账文本新增：已标记条数 / 未标记条数 / 基线指纹不符条数 / 链断提示。

**测试（新增 8 条）**：`自测-reconcile.mjs` 的 W5 改为"未标记=缺凭证、标记后才算 legacy"，新增 W5b（删字段伪装必须仍按缺凭证计）、W5c（标后改行=指纹不符）；新增 `自测-legacy基线.mjs`（LM-01…LM-05：无基线/链完整/幂等/篡改检出/冲突不覆盖）。

## 二·E、v0.6.3（P0 补丁）：真宿主"从未落账"的根因修复

> 触发：2026-11-10 晚机主重启 DSH 后实测 —— 面板 404、账本不写。诊断日志抓到：

```
tick catch Error: cannot get property "signal" without inject
    at runOnceCore (index.js:739)   // const signal = (cfg && cfg.signal) || (ctx && ctx.signal)
```

**根因**：Cordis 的 `ctx` 上访问**未 `inject` 的服务属性**会抛错；v0.6.2 及更早的 `runOnceCore` 直接读 `ctx.signal`，
于是**真宿主里每一轮 runOnce 刚进 core 就抛** → 插件从未在实机落过账（v0.6.1 同现象，正好解释 A12）。
所有进程内测试与子进程灌入用的是普通对象 ctx，不触发 Cordis 限制，所以 420 条测试全绿也没发现。

**修复**：取消对 `ctx.signal` 的直接读取（改为 try/catch 兜底 + 只认 `cfg.signal`）；
新增回归用例：构造"读 signal 就抛"的 ctx，要求 runOnce 仍正常落账。

**真机验证（修复后）**：`lastRunAt` 从 18:51:51 更新到 19:10:10，台账 24→31 行，运行报告刷新，面板 API 200、gate=ok。

**附带修复（同一事实）**：重启后宿主启动时 bundle 行未自动挂载（工具/API 缺失），用 `plugin_manager set_plugin` 禁用→启用
才挂上；说明 profile bundle 的启动加载存在时序问题，已记录待 v0.6.4 处理（不在本补丁范围内，避免混入不可逆改动）。

## 二·G、v0.6.5（A13 二次修复，P0 补丁）

> 触发：2026-11-10 20:10 机主重启 DSH 实测 —— **记账正常（lastRunAt 每分钟更新），但面板 404、无 `ledger_*` 工具**。
> 说明 apply 没崩，是"可选挂载"整段被静默跳过；v0.6.4 的修复（删直读回退 + 服务未就绪时 inject）仍不到位。

**根因（v0.6.4 修复为何无效）**：`ctx.get('tools')` 在服务未注入/未 ACTIVE 时**本身会抛**；
v0.6.4 把它写在 `if (ctx.get('tools'))` 条件里、外层又包了 try/catch → 异常被吞，
`else ctx.inject(...)` 分支根本没机会执行。热装能挂是因为那时服务已就绪、get 成功。

**修法（v0.6.5）**：可选挂载**永远优先 `ctx.inject`**（服务就绪即回调；未就绪则子 fiber pending，
headless 也不拖垮记账）；只有假 ctx（测试/宿主无 inject）才退化为安全 get（单独 try/catch，绝不阻断 inject）。
回归用例升级为"ctx.get 也抛"的假 ctx —— **修复前必红、修复后绿**，真机 20:10 现象被用例覆盖。

**真机验证**：装 0.6.5 后当前实例面板/工具立即恢复；**启动场景需再重启一次**，按 05 A13 与 `12-A13诊断.md` §5 验收。
