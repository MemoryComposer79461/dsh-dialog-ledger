# 16 · v0.6.3 修复记录（P0：真宿主从未落账）

> 性质：**P0 补丁版**（不含新功能）。依据：`项目批复` 之后的真装验证；机主 2026-11-10 晚重启 DSH 后实测。
> 数字以交付包 `07-发布页-0.6.3.md` 与 `_results/` 为准。

## 一、现象（真机，不是测试）

重启 DSH 后：
1. 左栏「会话账本」面板显示"只读服务未就绪 / HTTP 404"；
2. 账本停止增长：`.state.json` 的 `lastRunAt` 停在 18:51:51，日台账 24 行不变；
3. 宿主工具列表里也没有 `ledger_*` 工具（bundle 行未挂载）。

## 二、定位过程

1. 先用 `plugin_manager set_plugin`（禁用→启用）把行重新挂上：API 200、工具可用 → 说明**代码能加载**；
2. 但 `runOnce` 仍不执行：等待 70 秒 `.state.json` 不动、无 `.lock`、无新行；
3. 给 `apply/tick/runOnce/runOnceCore` 注入临时诊断（写桌面 `_dl-diag.log`），重装后拿到决定性日志：

```
apply enter enabled=true root=<build-host>\Desktop\会话账本 interval=60
before first tick
tick enter running=false
runOnce enter root=...
lock acquired=true
core enter
tick catch Error: cannot get property "signal" without inject
    at runOnceCore (...index.js:739:53)
```

## 三、根因

`runOnceCore` 里这一行：

```js
const signal = (cfg && cfg.signal) || (ctx && ctx.signal) || null;
```

Cordis 的 `ctx` 上访问**未 `inject` 的服务属性**会直接抛
`cannot get property "signal" without inject`。于是**真宿主里每一轮 runOnce 刚进 core 就抛异常**，
被 `tick` 的 catch 吞掉 → 插件从未在实机落过账。

**为什么当时 420 条测试全绿也没发现**：所有进程内测试、子进程灌入器用的都是普通对象 `ctx`（`{logger}`），
不触发 Cordis 的服务访问限制。这正是"只读推理/合成 ctx 永远看不出"的那类 bug。

顺带解释了两个旧谜团：
- A12「热装后定时器不跑」= 同一个异常；
- v0.6.1 装好后 `ledger_health` 一直 rows=0 = 同一根因（不是"真实账库为空"，而是根本没跑）。

## 四、修复

1. 不再直接读 `ctx.signal`：改为 `try { ctxSignal = ctx.signal } catch {}` 兜底，取消信号只认 `cfg.signal`；
2. 新增回归用例（`docs/自测-index-integration.mjs`）：构造"读 `signal` 就抛"的 ctx，要求 `runOnce` 仍正常落账
   （修复前该用例必红）。

## 五、真机证据（修复后，同一宿主）

| 项 | 修复前 | 修复后 |
|---|---|---|
| `state.lastRunAt` | 18:51:51（数小时不动） | **19:10:10 → 19:11:09**（周期 60s 连续跳） |

| 运行报告 | 18:51:51 | **19:10:11** 刷新 |
| 面板 API | 404 | **200**，gate=ok |
