## 一、本版五项（对应机主批复 / 目标）

### ① A13 修复：重启 DSH 后 Host 行不自动挂载（P0 级可用性）

- 根因（`_A13诊断.md`，只读宿主源码 + 真机）：Cordis 启动时**并发**创建全部条目；本插件 apply 顶层
  的 `registerLedgerTools` / `registerLedgerPanelApi` 有回退分支直读 `ctx.tools` / `ctx.webServer`，
  而 Cordis 4 对**未 inject 的服务属性**必抛 `cannot get property "tools" without inject`
  → apply 失败、fiber failed；Cordis 对 failed fiber 不自愈，启动审计只把错误写 stderr（不落盘/不进 GUI）
  → 界面表现只剩"面板 404 / 无工具"。热挂载能恢复是因为 set_plugin 会清 `_error` 重跑 apply（此时服务已就绪）。
- 修法：
  1. 删掉两处直读回退（`lib/toolface.js`、`lib/panelapi.js`）；
  2. 服务未就绪时用 `ctx.inject(['tools'], cb)` / `ctx.inject(['webServer'], cb)` 挂**子 fiber**，服务到齐后注册；
     headless 下子 fiber 保持 pending，**记账主职责照跑**（面板/工具仍是可选增强）；
  3. 新增回归 `docs/自测-a13启动挂载.mjs`：构造"读 tools/webServer 就抛"的假 ctx，要求 apply 不崩且走 inject 等待。
- 真机验证：**待机主下次重启时按 `_A13诊断.md` §5 执行**（重启后先别 toggle：查 `entryId=include:dsh-dialog-ledger-v05`
  的 `fiberPhase`；再做 5 个 `ledger_*` 工具 / `/dialog-ledger/api/ping` 200 / `state.lastRunAt` 三项验收）。

## 四、v0.6.5（A13 二次修复，2026-11-10 20:10 真机复测）

- **真机现象**：重启 DSH 后**记账正常**（`lastRunAt` 每分钟更新，20:11:35 仍在涨），但**面板 404 / 无 `ledger_*` 工具**。
  ⇒ apply 没崩，是"可选挂载"整段被静默跳过；v0.6.4 的修复（删直读回退 + 服务未就绪时 inject）**仍不到位**。
- **根因**：`ctx.get('tools')` 在服务未注入/未 ACTIVE 时**本身会抛**；v0.6.4 把它写在 `if (ctx.get('tools'))` 条件里、
  外层又包 try/catch → 异常被吞 → `else ctx.inject(...)` 分支根本没机会执行（热装能挂是因为服务已就绪）。
- **修法（v0.6.5）**：可选挂载改为**安全 get 优先**（服务已 ACTIVE 同步挂，热装/测试行为不变），
  get 抛错或无服务时再走 `ctx.inject` 等就绪；get 单独 try/catch，绝不让异常吞掉 inject 兜底。
- **回归**：`自测-a13启动挂载.mjs` 假 ctx 升级为"get 也抛"（修复前红、修复后绿）；
  toolface/panelapi 的 apply 生命周期测试改为累积 effect（真实 Cordis 行为）。
- **真机（热装后）**：面板 API 200、5 个 `ledger_*` 工具全部注册、rows 43、lastRunAt 20:19:41。
- **待办**：再重启一次做**启动场景**最终验证（本轮真机重启只验证到"v0.6.4 不足"）。
