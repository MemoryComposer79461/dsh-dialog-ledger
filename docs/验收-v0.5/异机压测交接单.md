# v0.5 异机压测交接单 · 36MB 档（P0-3 正式版闸门）

> 版本：v0.5.0-snapshot ｜ 编写：T3（stress）｜ 2026-11-09
> 一句话：**36MB 档是 v0.5 正式版的唯一内存闸门（发布闸 G1）；本机 TSG-02 因提交上限硬顶不跑，必须异机实测并把结果带回。**
> 口径：**异机压测只覆盖 P0-3**（1/4/16/36MB 内存曲线 + 36MB 单次完整验收），**不能替代其余判据**；其余判据仍以本机验收结果为准。

---

## 0. 先看这里（3 条铁律）

1. **不许 `--force-36` 跳过内存护栏**：可用内存 <900MB 时套件会自动跳过 36MB 档；跳过就如实写"未覆盖 + 原因"，强推 = 报告作废。
2. **同一时刻只跑一个测试进程**；套件内部已串行，别与其他 `node --test` / 压测并行。
3. **不要用真实 38MB 夹具**：必须用脚本自合成的 36MB 会话（`生成大会话.mjs` 已内建，流式写入）。

---

## 1. 要拷走什么

| 项 | 要求 |
| --- | --- |
| 目录 | 把整个 `docs/验收-v0.5/` 拷到异机插件的**同一相对位置**：`<插件根>/docs/验收-v0.5/` |
| 被测代码 | 同一插件根下必须有 `index.js`、`lib/`、`package.json`（单档工作进程会 `import ../../index.js`、`../../lib/*.js`；当前套件**不支持**把被测代码指到别处） |
| Node | **≥ 24**（用到内置 `zlib.zstdCompressSync/zstdDecompressSync`；低版本直接跑不了） |
| 网络/依赖 | **不需要**：不 `npm install`、不联网、只用 Node 内置模块 |
| 系统 | Windows / Linux 均可（不依赖 PowerShell、不依赖 git） |
| 内存 | 建议整机**可用 ≥ 2 GB**（36MB 档子进程 heap 上限 384MB；本机外推 RSS 峰 350–450MB，要给系统留余量） |
| 磁盘 | 临时目录 ≥ 500 MB 余量（合成会话落 `%TEMP%\v05-stress\`；压测自动清理实验室目录、保留会话文件以便复跑） |

## 2. 一条命令

```bash
# 在插件根目录执行（Node ≥24）
node "docs/验收-v0.5/跑压测.mjs"
```

默认就是四档 `1,4,16,36`，产物写到 `docs/验收-v0.5/压测结果/`。也可显式指定：

```bash
node "docs/验收-v0.5/跑压测.mjs" --tiers=1,4,16,36 --out-dir="docs/验收-v0.5/压测结果"

# 省时间只跑 36MB（注意：套件"内存曲线"断言至少需要 2 档才会判，单档会 exit=1）
node "docs/验收-v0.5/跑压测.mjs" --tiers=4,16,36
```

其他参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--heap=N` | 384 | 每档子进程 `--max-old-space-size=N`。**不要为了"跑过"而调大**（那是绕过有界性验收） |
| `--out-dir=...` | `docs/验收-v0.5/压测结果` | 产物目录 |
| `--force-36` | 关 | **验收禁用**，仅排障时不得用于交付结论 |

### 时间预期（本机 TSG-02 实测，供排期）

| 档 | 生成 + 两跑 + 断言 |
| --- | --- |
| 1MB | ~0.3 s |
| 4MB | ~1.1 s |
| 16MB | ~4.8 s |
| 36MB | 约 20~60 s（生成 1000+ 轮 + 两跑 + 周记账/交接表；以异机磁盘/CPU 为准） |

> 全四档一条命令约 1~2 分钟；失败时先看终端 stderr，再保留 `_原始-36MB.json` 与 `结果-*.json`。

## 3. 产物长什么样

| 文件 | 说明 |
| --- | --- |
| `结果-<主机名>-<yyyyMMdd-HHmmss>.json` | 机器可读总结果；**带回必须带这个** |
| `报告-<主机名>-<yyyyMMdd-HHmmss>.md` | 人读报告，三张表：**通过 / 失败 / 未覆盖** |
| `_原始-<档>MB.json` | 每档工作进程的原始结果（36MB 失败时**一定带回**，排障用） |

`结果-*.json` 关键字段：

- 环境：`hostname / platform / arch / node / cpuCores / totalMemMB / freeMemMBAtStart / heapLimitMB`
- 被测：`version`、`codeSha256`（`index.js`、`package.json`、`lib/*.js` 的 SHA256 + 字节数）
- 每档 `tiers[]`：`tierMB / pass / peakRssMB / durationMs / session{...} / ingest{written1,written2,ledgerRows,originals,weeklyBooks,handoverBooks,errors} / assertions{...} / failures / error`
- 顶层：`assertions{allExecutedTiersPass, memNotLinear, memDetail, fullAccept36, fullAccept36Detail, skippedTiers}`、`rssPeakByTier`、`pass`、`unfinished`
- 护栏：`skippedTiers[]`（被跳过档位 + 原因）

### 36MB 档算"通过"的硬条件（缺一不可）

1. `tiers[]` 里有 `tierMB=36` 且 `pass=true`；
2. 该档 `peakRssMB ≤ 600`；
3. 该档 `assertions.firstRunWroteAll=true` 且 `secondRunIdempotent=true`；即 `ingest.written1` = 轮数、`written2=0`、`ledgerRows=originals=轮数`、`weeklyBooks≥1`、`handoverBooks≥1`、`errors=[]`；
4. 顶层 `assertions.fullAccept36=true` 且 `pass=true`；
5. 人读报告 §3「未覆盖」里**没有** 36MB 行。

## 4. 带回后怎么并入（三步，照做即可）

**第 1 步 · 放回并合并**：把 `结果-<主机名>-<时间>.json`（连同 `报告-*.md`、`_原始-*.json`）拷回本机任意目录，例如 `docs\验收-v0.5\压测结果\异机-TSG-XX\`，然后执行：

```powershell
node "docs\验收-v0.5\合并异机结果.mjs" --remote-dir="docs\验收-v0.5\压测结果\异机-TSG-XX"
```

→ 生成两份：`docs\验收-v0.5\异机结果合并-<时间>.md`（人读「本机 / 异机」两栏对照表）与同名 `.json`（机器可读，含各主机原始 assertions 与逐判据两栏状态）。

**第 2 步 · 核对生成的对照表**：

- ① 异机运行清单：主机 / 平台 / Node / CPU / 内存 / 被测 version / 档位结果 / RSS 峰 / 总体；
- ② P0-3 一行的异机栏是「通过 ✅」还是「未通过 ❌」；
- ③ **比对 `codeSha256` 与本机是否同一份被测代码**——不一致不得把两边数字混谈（合并脚本会原样列出清单，请人工确认）；
- ④ **务必把 `--remote-dir` 指向"只含异机结果的新建子目录"**（如第 1 步的 `异机-TSG-XX\`）：合并脚本会把该目录下**所有** `结果-*.json` 都当作异机结果读取，直接指向 `压测结果\` 会把本机/历史样本一起混进"异机清单"；
- ⑤ 若本机总表 `docs\验收-v0.5\_results\结果-v0.5.json` 尚未生成，对照表的「本机」栏会显示缺失/未覆盖——那是**本机验收总表尚未产出**，不是异机结果的问题；交付前先把本机总表补齐。

**第 3 步 · 交付里并列两栏**：在验收记录 / 交付包中写「本机（TSG-02：1/4/16MB 曲线 + 其余判据）｜异机（<主机名>：36MB 实测）」两栏；36MB 结论只写异机实测值，**外推值不作结论**。

> ⚠️ 合并脚本的覆盖口径是写死的：**异机只覆盖 P0-3**；其余判据在异机栏显示「—（不覆盖）」，仍以本机验收结果为准。避免"异机没跑却算通过"。

## 5. 如果 36MB 失败 / 被跳过（如实带回）

必须带回以下最小证据：

- 终端 stderr / 崩溃特征（例如 `Fatal process out of memory`、`JavaScript heap out of memory`、exit code、是否超时）；
- `结果-*.json` 里的 `failures` / `error`，以及 `_原始-36MB.json`（若有）；
- 异机可用内存、是否被 900MB 护栏跳过（`skippedTiers[].reason`）；
- 明确写"是否换过机 / 重跑过几次"。

> 这不是丢人事：**"本机/异机都跑不动"本身就是给机主的结论**。但**不许用 `--force-36` 或改大 heap 假装通过**。

## 6. 已知坑（都实锤过）

- 受限沙箱下用 pipe 捕获子进程输出会 `EPERM` → 套件固定 `stdio:'inherit'`，别改成 pipe；
- 裸 cfg 直接调 `runOnce` 会让 `eventBatchTurns` 变 `undefined` → 批次循环一次不跑、`written=0` 像"没活干"（套件 1/4/16/36 档都走 `index.runOnce` 入口 + 默认值兜底，别绕过）；
- 内存护栏阈值与 `docs/跑测试.mjs` 一致（900MB）；
- 别动 U 盘、冻结包、契约目录；不跑 git、不 `npm install`。
