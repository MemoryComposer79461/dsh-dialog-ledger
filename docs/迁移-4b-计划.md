# 迁移计划（4b）：周记账改名 / `-B` 补记 / 命名统一

> 触发：v0.4 若采纳《架构设想》的字面命名（"前12位编码 + 周记账"、补记编码 `-B`），
> 已有周记账文件需要**一次性改名重生成**。
> 原则：迁移是独立工程，不混在"交接表"里顺带做；**旧文件不删，只归档**。

---

## 一、要迁什么

| 现状 | 目标（待口径确认） | 影响面 |
|---|---|---|
| `MM月第W周-{13位会话键}的周记账.xlsx` | `{前12位}-周记账.xlsx` 或保留 13 位 | 文件名规则 |
| 补记在「备注」列写"补记" | 编码列加 `-B` 后缀 | 编码格式 **（与"编码永久主键"冲突，需慎重）** |
| 周记账 7 列（含「原文」） | 待定 | 列结构 |

> ⚠️ **`-B` 与主键原则冲突**：编码是永久主键，加后缀等于改主键。
> 更安全的做法：**新增「补记」标记列/字段**，编码不动。建议不采纳 `-B`。

## 二、迁移流程

```
1) 盘点：扫描所有 xlsx，导出清单（路径 / 大小 / hash / 会话键 / 周段）
2) 预演（dry-run）：算出"新文件名 → 旧文件"映射，不落盘
3) 确认：输出将影响的文件数与总大小；失败即停
4) 执行：
   a. 旧文件移动到 <root>/_迁移归档-YYYYMMDD/ 保留原相对路径
   b. 清空对应 weeklyHashes 条目 + 设置 layout 迁移标记
   c. 下一轮扫描按新规则全量重生成（可分批：每轮最多 N 组）
5) 校验：新旧内容逐行对比（除命名/版式外应等价），输出差异报告
6) 回退：归档目录移回 + 清迁移标记
```

## 三、代码改动点

| 文件 | 改动 |
|---|---|
| `lib/week.js` | 文件名规则（唯一出口，已在用） |
| `lib/weekly.js` | `LAYOUT_VERSION` +1；列结构；补记标记 |
| `index.js` | bootstrap 判定加"迁移标记"（与 F1 的 offsetStale 同机制） |
| `docs/工具-v04-迁移.mjs`（新） | 盘点/预演/执行/校验/回退 |

## 四、判据

1. 迁移可 dry-run，输出影响清单；
2. 执行后旧文件全部在归档目录（不丢）；
3. 重生成后：每组一份、行数和台账一致、原文四态正确；
4. 回退一次后文件与迁移前逐字节一致。
