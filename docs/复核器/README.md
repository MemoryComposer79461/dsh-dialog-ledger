## 四、与「插件自身重放」的差异（审计要看的口径）

| 维度 | 插件自身重放（`docs/replay-verify.mjs`、`docs/工具-日检.mjs`） | 本目录独立复核 |
|---|---|---|
| 代码来源 | 插件自己的 `lib/*` 实现 / 判据执行器 | 两套独立实现，只 import Node 标准库 |
| 验证对象 | 逐字段重放原始事件 ↔ **原始事件.json 内容**（C09/C14–C16） | 轮数/唯一性/体积/帧完整性 **↔ 台账/tick 度量/索引**（不逐字段重放内容） |
| 轮次口径 | 插件 `turn/start..turn/end` 配对 + 状态机（含 abandon/legacy） | 独立复核：源侧只认 `turn/end` 条数（v4=1,338）+ 归档版按 0.8 裁定口径配对（1,339=1,338 闭合+1 未闭合） |
| 能发现 | 内容被改、字段被改、附件被改 | 台账被删/多算/重复、轮数对不上、帧损坏、索引与台账不一致 |
| 不能发现 | 如果插件配对逻辑本身错，重放会一起错 | 不验内容哈希与附件字节（那是 C09/C14–C16 的事）；也不验插件 tick 的读盘预算（C21/C25） |

**归档复核器的已知历史口径**（复制自其文件头，未改）：v0.8 裁定 R1 规定 `turn/end..turn/start` 之间、且 `data.turn` 为空或等于本轮的 `tool/result` 事件计入本轮；`data.turn` 指向其他轮次的回放事件不计入（计入 `foreignTurnEventsExcluded`）。该规则与当前插件 `readTurnEventsBatch` 的过滤一致，但**代码不共享**；E3 上 A–E 全 0 说明这批源数据没有触发该分支。
