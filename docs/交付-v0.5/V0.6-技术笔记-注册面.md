## 一、Host 侧（模型可见的工具）

### 1. 工具注册 **[已查证]**
Service `tools`（`ctx.tools`）方法：

### 2. 工具是否自动出现在模型上下文 **[推断，待确认]**
`systemPrompt` 有 `tools(provider: (context) => ToolProviderResult)` 方法——说明工具清单可以由 provider 动态给出。
我们的诉求是"**让 Agent 知道工具存在，但不注入账本内容**"，所以正路是：注册成普通工具（工具名+描述进模型），
**不**用 `systemPrompt.context()` 注入任何账本摘要（那是"内容占上下文"，被明确否掉）。

### 3. 若面板需要数据接口 **[已查证]**

→ 面板要读账本数据，可由 host 注册一个**只读 HTTP 路由**（如 `/ledger/api/summary`），client 面板 fetch 它。

## 五、ToolDefinition 精确契约 **[已查证 · 2026-11-09 22:2x]**

来源：`cordis_inspect_query(host/Service, {service:"tools"})` 返回的 referencedTypes。

```ts
interface ToolSchema {
  deferLoading?: true;          // ★ 见下方"意外收获"
  name: string;
  description: string;
  parameters: Record<string, unknown>;   // JSON Schema（JsonSchemaNode 子集）
}

interface ToolDefinition extends ToolSchema {
  readonly output: ToolOutputDefinition; // { schema, render(args,value)=>ContentBlock[], presentationMeta? }
  execute(args: unknown, exec: ToolRunContext): Promise<unknown>;
  projectContent?(exec, result): ContentBlock[] | undefined;
  finalizeContent?(exec, result): ContentBlock[] | undefined;
  timeoutMs?: number;
  isConcurrencySafe?(args): boolean;
  presentCall?(args): ToolCallView | undefined;        // ★ 工具"调用中"卡片
  presentResult?(args, result: ToolResult): ToolResultView | undefined;  // ★ 工具"结果"卡片
}

interface ToolRegistrationOptions { when?: (ctx: ToolActivationContext) => boolean | Promise<boolean>; }
interface ToolActivationContext { agent: Agent; modelSelection; signal: AbortSignal }
type ToolCallKind = 'read' | 'edit' | 'delete' | 'move' | 'search' | 'execute' | 'fetch' | 'other';
```

### 意外收获 1：`deferLoading?: true`
`ToolSchema` 上有这个可选字段——含义应为"**工具先只暴露名字与描述，完整 schema 延迟到需要时再加载**"。
这正好是机主要的"**让 Agent 知道工具存在，但内容不占上下文**"的原生机制！
→ 明天要先验证它的确切语义（是延迟 schema，还是延迟整个注册）。

### 意外收获 2：`presentCall` / `presentResult`
**工具卡片不需要写客户端插件**：在 `ToolDefinition` 上实现这两个方法即可返回 `ToolCallView` / `ToolResultView`。
`ToolResultView` 已有 `search` / `read` / `generic` 等卡片形态：
- `SearchResultView`（`shape:'matches'`，带 `files[].matches[]`）——我们的 `ledger.search` 可直接用；
- `ReadResultView`（`path/offset/lines/totalLines`）——`ledger.turn` 可复用；
- 兜底 `GenericResultView`（`card:'generic'` + `content: ContentBlock[]`）。

→ **V0.6 可以砍掉一个施工项**：工具卡片不用碰 client 侧，先做 `presentResult` 即可；
  左栏面板仍需要 client 注册 API（那一半还是 **[待查]**）。

### 签名落点（写代码时照抄）
