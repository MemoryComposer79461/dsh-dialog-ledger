# 04 · 回滚方式（v0.5 正式候选 0.5.0-rc.1 → v0.4.0 正式版）

> **原则：代码可回滚，档案不可回滚。**
> 数据总库是 append-only 的事实文件；回滚代码不会撤销已经写下的账、凭证、周记账与封板证据，只影响"以后怎么记"。
> 本页按"**停插件 → 恢复 v0.4 目录 → 校验哈希**"三步写，每步都附可复跑验证命令。

| 项 | 路径 |
|---|---|
| v0.5 正式候选（当前） | `<test-dir>\work\v0.5-工作副本` |
| v0.4.0 冻结包（回滚目标，**只读**） | `<build-host>\Desktop\交付包-全量-20261109\06-v0.4冻结交付包\`<br>`记忆插件v0.4.0-正式版-交付\01-代码` |
| 交付包全量 MANIFEST | `<build-host>\Desktop\交付包-全量-20261109\MANIFEST.sha256` |
| DSH profile | `<build-host>\.dsh\profiles\desktop\`（`package.json` + `cordis.patch.yml`） |

---

## 第 0 步（建议，2 分钟）：备份数据总库

```powershell
# 先停插件再备份（避免备份过程中还在写）；<root> 换成真实数据总库路径
Copy-Item -LiteralPath '<root>' -Destination "<root>.bak-$(Get-Date -Format 'yyyyMMdd-HHmmss')" -Recurse
```

> 备份是"全量复制"；恢复时**整体覆盖回 `<root>`**，不要只挑文件。
> 若只想回到某天的账：从 `<root>.bak-*` 复制对应 `ledger\YYYY-MM-DD.jsonl` 即可（台账按天分文件）。

---

## 第 1 步：停插件（v0.5）

**方式 A（推荐）**：DSH 插件管理界面 → 停用/移除 `dsh-dialog-ledger-v05`。

**方式 B（等价，改 profile 文件）**：

1. 编辑 `<build-host>\.dsh\profiles\desktop\package.json`，在 `dsh.profile.bundles` 里**删掉** `"dsh-dialog-ledger-v05"`（若不存在则跳过）。
2. 检查 `<build-host>\.dsh\profiles\desktop\cordis.patch.yml`：**不得**有手写 `insert` 的 `dsh-dialog-ledger-v05`（本包的接入方式是包名列进 bundles，不要再手写 insert，否则 duplicate loader entry）。
3. 重启 **Harness 应用**（不是重启系统——本机重启即回滚，任何"重启系统才生效"的方案都不成立）。

**验证（必须看到）**：

- 插件列表里已没有 `dsh-dialog-ledger-v05`；
- 新日志里不再出现 `[dsh-dialog-ledger] loaded ｜ root=...`；
- 等一个扫描周期（默认 60s）后，数据总库 `ledger/` 不再有新文件写入。

## 第 2 步：恢复 v0.4 目录

**方式 A（推荐）**：DSH 插件管理器 → "安装本地插件"，指向
`<build-host>\Desktop\交付包-全量-20261109\06-v0.4冻结交付包\记忆插件v0.4.0-正式版-交付\01-代码`
（该目录自带 v0.4 的 `cordis.patch.yml`，loader id/name = `dsh-dialog-ledger-v04`）。

> ⚠️ **不要动桌面冻结包本身**：只"指向"或"复制"上述 `01-代码` 目录使用；
> **禁止**在冻结包目录内修改/覆盖/删除任何文件（它是审计基线，一字节都不能动）。
> 回滚时也不要把 v0.5 的文件拷进冻结包目录"覆盖成旧版"——正确做法是让插件指向 v0.4 目录。

**方式 B（等价，改 profile 文件）**：把 `"dsh-dialog-ledger-v04"` 加进 `dsh.profile.bundles`，并确认**没有**手写 insert。

**硬要求**：

- 同一 profile **只能挂一个** dialog-ledger：`dsh-dialog-ledger-v04` 与 `dsh-dialog-ledger-v05` **不得同时存在**（会双实例各写各的）。
- 若 v0.4 是"复制到某目录再安装"的，复制目标必须来自冻结包原目录（不要用 `01-工作副本-v0.5` 里的旧副本）。
- 不要在 v0.4 代码目录里改任何文件（冻结包一字节都不能动）。

## 第 3 步：校验哈希（回滚是否成功，看这一步）

### 3.1 核心文件逐个校验（前 16 位，与 v0.4 `00-交付清单.md` 对照）

```powershell
$target = '<build-host>\Desktop\交付包-全量-20261109\06-v0.4冻结交付包\记忆插件v0.4.0-正式版-交付\01-代码'
Get-ChildItem -LiteralPath $target -File -Recurse |
  Where-Object { $_.Name -in @('index.js','package.json','cordis.patch.yml','README.md') } |
  ForEach-Object {
    $h = (Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256).Hash.ToLower().Substring(0,16)
    '{0}  {1}' -f $h, $_.Name
  }
```

期望（v0.4 交付清单原文）：

```
4a6ccdffcceefb6a  index.js
6d1481b9c235e442  package.json
4c61e13368dc6812  cordis.patch.yml
c9b8bee77a974041  README.md
```

### 3.2 冻结包子树全量校验（89 条，发布闸门 5 要求）

```powershell
Set-Location '<build-host>\Desktop\交付包-全量-20261109'
# ★ 必须转绝对路径：[System.IO.File] 不跟随 PowerShell 的 Set-Location
$manifest = (Resolve-Path -LiteralPath '.\MANIFEST.sha256').Path
$all  = [System.IO.File]::ReadAllLines($manifest, [System.Text.Encoding]::UTF8)   # ★ 必须 UTF-8，否则中文路径乱码
$rows = @($all | Where-Object { $_ -match '^\S{64}  06-v0\.4冻结交付包\\' })
"清单 06-* 行数=$($rows.Count)"
$bad = 0; $n = 0
foreach ($line in $rows) {
  $parts = $line -split '  ', 2; $n++
  $actual = (Get-FileHash -LiteralPath $parts[1] -Algorithm SHA256).Hash.ToLower()
  if ($actual -ne $parts[0].Trim().ToLower()) { $bad++ }
}
"一致 $($n-$bad) / 不一致 $bad"
```

期望（2026-11-09 实测）：

```
清单 06-* 行数=89
一致 89 / 不一致 0
```

> ⚠️ 不要用 `Get-Content .\MANIFEST.sha256`（默认编码）读：中文路径会乱码，导致全报 MISMATCH。
> 若哈希不一致：先从冻结包原目录重新复制，**不要继续启动**；仍不一致说明源包被改过，立即报机主。

## 回滚的副作用（必须知道）

| 副作用 | 说明 |
|---|---|
| 周记账可能全量重写一次 | 若旧版本 `LAYOUT_VERSION` 判定不一致会重算并重写**草稿**；已封板的按文件头明文认领、不重写。**回滚前先备份 root** |
| 封板识别的边界 | v0.5 封板 xlsx 默认 **stored（不压缩）**，v0.4 能用明文扫描识别封板标记；但若 xlsx 曾被 **Excel 重存（deflate）**，旧代码可能认不出 → 会把该册当草稿重写。**先在一份 root 副本上试跑再操作生产库** |
| v0.4 不认 v0.5 新证据文件 | `.seal-journal.jsonl`、`.pending.jsonl`、`.run-report-*.json`、`.cleanup-*.journal`、`RPT-DRYRUN-*.md` 旧代码不读也不删——**保留**，不要手工清理 |
| 台账新字段 | `docSha256/docFileSha256/attachment/late` 旧代码按未知字段忽略，不报错 |
| 收据锚 | 库外目录，旧版不写；已有收据文件保留，可用 `docs/工具-核验收据.mjs`（新版工具）继续只读核验 |
| 交接表状态 | state 丢失时 v0.4 会按"重新开账"处理并显式告警（设计内降级，不是故障） |

---

## 不可回滚点（回滚只回代码，不回证据/档案）

1. **已写下的台账行、完整原文、周记账、交接表**：append-only/封板即事实，回滚不撤销。
2. **`.seal-journal.jsonl` 封板链、`.lost.jsonl` 缺口留痕、收据链**：证据不允许删；删了等于破坏审计基线。
3. **已物理删除的原文**（只有显式开启双开关才会发生）：删了无法从代码回滚找回，只能从备份恢复。
4. **v0.5 曾写下的 `.pending.jsonl`**：旧代码不消费，但它是"某轮当时未闭合"的现场证据，保留。
