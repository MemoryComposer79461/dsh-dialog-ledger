# 07 · 契约增补草案 v0.5.1（legacy 行口径）· 待机主/Lead 裁定

> 性质：**草案**。按项目铁律「改口径必须升版 + 出差异清单」，本文件是 v0.5 → v0.5.1 的增补提案与影响清单。
> 触发原因：`05-已知未覆盖项` #7 —— 历史 v0.4 行恒为「缺凭证」，导致老账库的 `okStrict` 永远是 `unknown`。

---

## 一、问题（事实层）

契约 `v0.5-P1可信链契约.md:38` 规定：历史 v0.4 行无 `docFileSha256/attachment` → `LEGACY_NO_ATTACHMENT`，**永远不得 bound**。
`reconcile()` 按 RC-01 的 `ok` 公式把这类行计入 `originalMissing` → `ok=false` → `okStrict=false`。

后果：**含任何历史行的账库，闸门永远红**。闸门于是从"报警器"退化成"常亮灯"，人就会开始无视它 —— 这是审计最反对的形态。

## 二、增补提案 D18（legacy 行单列，不改"永不 bound"）

**D18**：`reconcile()` 的输出增加两个字段：

| 字段 | 含义 |
|---|---|
| `legacyUnverifiable: Array<{code, doc, reason:'LEGACY_NO_ATTACHMENT'}>` | 视图文件**物理存在**、但台账没有绑定证据的行（历史 v0.4 行） |
| `legacyUnverifiableCount: number` | 上述条数（与数组长度自洽） |

**判定顺序**（写死，避免解释空间）：
1. `resolveDoc().state === 'cleaned'` → 合法销毁，跳过（不变）。
2. 视图文件**不存在** → 仍进 `originalMissing`（真的缺凭证）。
3. 视图文件**存在**、`integrity.problems` 含 `LEGACY_NO_ATTACHMENT`、且附件不缺失 → 进 `legacyUnverifiable`，**不进** `originalMissing`。
4. 其余（哈希不符 / 路径不符 / 附件不符）→ 仍进 `originalMissing`（这是篡改或损坏，不是"没证据"）。

**`ok` 公式不变**（RC-01 仍是 6 项）；变化只在**输入**：`originalMissing` 不再包含第 3 类。

## 三、明确不变的事（防止被误读为放宽）

1. **CH-01 不变**：历史行**永远不得 bound**；周记账 B 列仍写 `缺凭证`（v1.3 四态不变）。
2. **不新增"自动补齐证据"**：v0.5 仍不做历史证据回填（那需要独立的、可审计的迁移流程）。
3. **不隐藏**：这些行仍在 `legacyUnverifiable` 里逐条列出（code + doc），运行报告与对账文本都要显示条数。

## 四、差异清单（v0.5 → v0.5.1）

| # | 位置 | 变化 | 兼容性 |
|---:|---|---|---|
| 1 | `lib/reconcile.js` 返回值 | 新增 `legacyUnverifiable[]`、`legacyUnverifiableCount` | 新增字段，老读法不受影响 |
| 2 | `reconcile.originalMissing[]` | 不再包含"文件在但无绑定证据"的行 | **行为变化**：老账库的 `ok` 可能由 false 变 true |
| 3 | `formatReconcileReport()` 文本 | 增加一行 `历史无证据 N 条（legacy）` | 文本新增行 |
| 4 | `05-已知未覆盖项` #7 | 由"未处置"改为"已按 D18 单列" | 文档 |
| 5 | `06-正式版闸门` 门 2 | 缺口 ② 保持（P1-13 已实现，见 W3）；本条从"待裁决"变"待机主确认 D18" | 文档 |

## 五、风险与反证

- **风险**：若有人把"篡改"伪装成"legacy"（例如删掉台账里的哈希字段），会不会被判成 legacy 而漏报？
  → **不会**：第 3 类的条件是"文件在 + 问题**仅**含 `LEGACY_NO_ATTACHMENT` + 附件不缺"。
  一旦正文哈希不符，`problems` 里会出现 `BODY_HASH_MISMATCH` 等，走第 4 类，仍进 `originalMissing`。
  **待补**：一条以"删哈希字段伪装 legacy"为攻击面的用例（列入 W7 证据包）。
- **反证**：`自测-reconcile.mjs` 的 `W5` 用例断言"文件在、无证据 → legacyUnverifiable 且不进 originalMissing"；
  既有的"缺一份原文 → originalMissing"用例仍必须绿（真的缺，仍报缺）。
