# 交接表（表头目录）设计 · v0.4

> 依据：《架构设想》模块 2；《口径定稿-v0.4》口径 2。
> 代码：`lib/handover.js`（已实现，未接线）；测试：`docs/自测-handover.mjs`（5/5）。

---

## 一、产物

| 文件 | 位置 | 说明 |
|---|---|---|
| `{S}{D}的启用及交接表.md` | 一级 | 主表：会话键/ID/起账编码/启用时间/记录范围/数据总库/附表指针 |
| `{S}{D}的启用及交接表——附表.md` | 一级 | 附表：**安装前上下文**（只收 user 消息，超限截断） |

两份都有 YAML 前置块；主表带 `封板: true` + `封板hash`（覆盖正文）。

## 二、生命周期

```
第一次扫描到该会话（已入账） 
   → decideHandover(): generate → 写主表+附表 → markSealed(state) → 落盘 state
之后每一轮 
   → skip（即使文件被删也不重建）
state 丢失
   → 重新 generate（视为重新开账，允许）
```

## 三、关键取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 附表内容 | 只收 `user/message`（kind=user），默认上限 8000 字符 | 附表是"备份上下文"，不是第二份完整原文 |
| 超限 | 截断 + 提示"原文本体见第 3 级凭证" | 避免附表膨胀、避免与原文职责混淆 |
| 已有文件 | `adopt`（只补封板，不重写） | 手工/旧版放入的交接表不能被覆盖 |
| 封板位置 | `.state.json` + 文件头 | state 防删、文件头可搬可读 |

## 四、接线计划（下一步）

在 `index.js` 的会话循环里（**凭证与周记账之后**）：

```
对每个本轮有记录、且 decideHandover() !== 'skip' 的会话：
  1) 从会话头取 sid/createdAt；从该会话第一条台账记录取 firstCode/lastTurn
  2) 读"首轮入账之前"的事件（readTurnEventsBatch(turn=1) 之前，或直接 readSessionFrom 的前段）
  3) renderMain + renderAppendix → writeHandover → markSealed
  4) 失败只记 errors，不影响记账
```

注意：附表需要"安装前上下文"，即第一条 `turn/start` 之前的事件；
若首轮就是会话第一条（无上下文），附表写"（无安装前上下文）"。

## 五、验收判据（v0.4 发布用）

1. 新会话首次入账后，一级目录出现主表 + 附表；
2. 重复扫描 mtime 不变（不重写）；
3. **删除主表后，后续扫描不再生成**（本次已测）；
4. 主表字段与台账首条记录一致（独立脚本重算比对）；
5. 附表不出现注入类消息（`runtime-context` 等）；
6. 清理工具拒绝删除一级文件（已有拦截）。
