# 04 · 回滚方式 · `v1.0.0-re4`

> 纪律：**代码可回滚，档案不可回滚。**
> 本机/异机都没有 git、交付包内也没有 `.git`——**回滚不使用 `git reset`**。本版回滚物**不随包携带上一版二进制**；回滚目标是 **v1.0.0-re3 送审包**（三份审计的对象本体）+ 锚值。
> 路径基准：相对 `01-插件包/`；`../` = 交付根。写稿时点：2026-11-14 20:52 +08:00；定稿回填：2026-11-14。

## 一、回滚目标与锚（缺一不可）

本包 `../回滚/` 只有 `sha256.txt` + `怎么回滚.md`，**没有 zip**（`../回滚/怎么回滚.md:4`）。目标机必须另外拿到 re3 送审包，三方锚一致才可用：

| 锚 | 值 | 物证 |
|---|---|---|
| zip 文件名 | `异机检测包-lite-v1.0.0-re3-20261114.zip` | `../回滚/sha256.txt` |
| zip sha256 | `c5dab0b717b948b93d90aa8763d93d95d114b7f0b771102b9a9f3ad7a762afe4` | 同上 |
| zip 字节数 / 条目数 | 59,098,821 B / 761 条目 | 同上 |
| 内层文件数 / 清单行数 | 730 / 729（不含 MANIFEST 自身） | 同上 |
| 内层 `MANIFEST.sha256` sha256 | `a9f837dcbe0d6bee1ba8e1e0e08059dc3d9f703585cc435c6d77f26ff6549383` | 同上 |

- **取舍（如实写）**：re4 不随包带上一版二进制，原因是 re2 时代的回滚 zip 内含开发期真实标识，扫描命中 **196 条目**（`../回滚/sha256.txt`）。收益：交付包不含那 196 个对象（该 zip 移出后问题消解）；代价：**回滚能力依赖“可核验的上一版锚”，接收端必须另行取得 re3 包**。拿不到 re3 zip 时，回滚不可执行——不能假装包内能回滚。
- 更早的 `v0.9.5-snap` 不在包内，也不在本文件保证范围；需要时从历史交付包取。

## 二、回滚步骤（手工版，Windows）

```powershell
# 0) 先停插件：插件管理器停用，或从 profile 的 dsh.bundle 移除包名；确认没有 tick 在跑
# 1) 取到 re3 送审包后，先核锚（sha256 必须等于 §一 的值）
Get-FileHash "<re3 zip>" -Algorithm SHA256
# 2) 解压到临时目录（例如 %TEMP%\rb-re3）
Expand-Archive "<re3 zip>" -DestinationPath "$env:TEMP\rb-re3" -Force

# 3) 用本包（re4）自带的清单工具复核 re3 内层清单：期望 729/729、缺0/多0/改0
node "<当前 re4 包>\01-插件包\docs\工具-manifest.mjs" --root="$env:TEMP\rb-re3\异机检测包-lite-v1.0.0-re3-20261114\01-插件包" --verify

# 4) 备份当前包与账库（回滚不删档案，但先备份永远是对的）
Compress-Archive -Path "<当前 re4 包目录>\*" -DestinationPath "D:\回滚备份-re4-<日期>.zip"
Compress-Archive -Path "$env:USERPROFILE\Desktop\会话账本" -DestinationPath "D:\回滚备份-账库-<日期>.zip" -ErrorAction SilentlyContinue

# 5) 停插件后，用 re3 代码镜像覆盖当前安装目录（/MIR 会删掉 re4 独有文件——预期行为）
robocopy "$env:TEMP\rb-re3\异机检测包-lite-v1.0.0-re3-20261114\01-插件包" "<当前安装目录>" /MIR /NFL /NDL /NJH /NJS /NP

# 6) 回滚后三件确认
#    a. 插件管理器版本号 = 1.0.0-re3
#    b. node docs\工具-身份一致性.mjs → 7/7 PASS
#    c. 账库自检 / 台账行数不得比回滚前少
```

- 采用 `/MIR` 时，re4 新增的 `docs/自测-v3跨帧轮-re4.mjs`、`docs/退役登记.json`、`docs/工具-出包门.mjs`、`docs/工具-收尾校验.mjs`、本目录 `交付-v1.0.0-re4/`、`证据/交付-v1.0.0-re4/` 会被删除——这是**预期**：回滚就是回到 re3 状态（`../回滚/怎么回滚.md:30`）。
- **不许**对账库根做任何覆盖/回退（默认 `<桌面>\会话账本`）；回滚只回代码。
- 同一 profile 不要同时挂 re3 与 re4；装回 re3 前先移除 re4。
- 包内自动化版：本版**不提供** `_工作\tools\回滚演练.mjs`（开发树工具，不随包）；不要照抄旧文档的 `_工作` 路径。

## 三、回滚后的真实代价（必须知情）

1. **K-16 修复丢失**：re3 没有 `readTurnEventsBatch` 的 `truncated` 出参/短读判定（`lib/ledger.js`、`index.js` 的相关修复只在本版）。回滚后 **v3 跨帧轮又会被截断**：`attachment.bytes` 从完整 **51,723 B** 落成 **71 B**，设备自检 c19 会再报 **6 条 FIELD_MISMATCH**。依据：`VERSION.json:142`、`docs/自测-v3跨帧轮-re4.mjs:6-16`、`../回滚/怎么回滚.md:44`。这是回滚的真实代价，不是“零扰动”。
2. **re4 独有工具/文档消失**：出包门、13 项收尾校验、三台收件单 schema、本目录六件、`docs/退役登记.json` 等都不存在于 re3；回滚后复核口径回到 re3，不能再用 re4 的 13 项/收件协议。
3. **判据执行器退回 re3 版本**：K-17 的 C42 `v>=3` legacy 门不存在（该门本来就受 S-15 签字约束，未签则回退）；K-18 的 lab 版本根/指纹重建不存在，旧行为是复用 `%TEMP%\dsh-ledger-labs-v1.0.0-re2`；K-19 的新回滚法名（A 锚核验 / B 覆盖安装 / C 回滚后确认）与 K-20 的 summary“证据目录”行对齐同样不存在。
4. **账库数据不迁移、不受影响**：台账 `v:3`、目录布局、原文/附件/周账/月账格式在 re3/re4 相同；回滚只换代码（`交付-v1.0.0-re3/03-变更说明.md:45` 同口径）。
5. **日结摘要口径**：按本版变更清单（`VERSION.json:130-146` 的 K 项）没有 `lib/receipt.js`；按包内 re3 文档，re3 起 `RECEIPT_VERSION=3`、`originalCount=当日视图数`（`交付-v1.0.0-re3/03-变更说明.md:45`）。故回滚不应把摘要语义退回“全库累计”。`../回滚/怎么回滚.md:42` 写“re3 的 originalCount 是全库累计旧口径”，与上述 re3 文档**不一致**；本文件不采用该句，登记为 05 H-8 待 lead 确认（包内无 re3 原件可逐字节对照；本版回滚演练只做锚核验/覆盖安装/回滚后确认三法，不含摘要口径的字节比对，故此处不下实测结论）。
6. **冻结的 `freeze/`、历史证据**：re3 包内同样保留；回滚不会改账库的 `.lost.jsonl`/`.tick-metrics.jsonl`，新字段 additive。

## 五、什么情况**不要**回滚

- 账库本身有问题（坏帧/未闭合轮/摘要过期）：那是数据面，回滚代码不修数据；先备份、再按数据流程处理。
- 只是面板/工具报错：先看 05 已知边界；不要用回滚当排障手段。
- 已经发过日结摘要给别人：回滚会让版本号断档；先补发一次再回滚，或保留 re4 只停用。
- 拿不到 re3 送审包或锚值对不上：**不要回滚**（没有可核验目标，等于盲装）。

**回滚的真实代价（不许美化）**：回滚到 re3 会**丢掉 K-16 截断修复** —— v3 跨帧轮的附件会再次从 51,723 B 被截成 71 B。要保留修复就别回滚，或回滚后立刻重新升级。
