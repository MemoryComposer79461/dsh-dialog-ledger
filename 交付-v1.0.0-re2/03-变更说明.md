### 2.1 C42 带来的产品改动（唯一实质功能补齐）

**背景**：S-11 §2 F7 写"日结摘要 txt 可外发"，实测发现①摘要无 `firstCode`（只有 `lastCode`）②`renderDailyDigest()` 只是函数、**没有任何 .txt 落盘**③改台账后摘要**原地重写**。三条都与 C42 直接冲突；S-11 后签，口径优先于旧 S-1「坏了重出即可」。

**改动**（`lib/receipt.js` + `index.js` 收据接线处）：

1. 摘要 JSON 由 **10 键 → 11 键**：新增 `firstCode`（与 `lastCode` 对称）；
2. 落盘日结摘要 **.txt**：`日结摘要-YYYYMMDD.txt`（v1）→ 内容变化补发 `日结摘要-YYYYMMDD.v2.txt`、`.v3.txt`…；
3. **永不覆盖、永不删**已发出的任何版本；tick 发现当天已有版本且内容不同 → 写下一版并在运行报告里记一条（可观测）；
4. 旧 10 键摘要文件读取兼容（缺 `firstCode` 视为旧格式，可重出）；
5. 自测：firstCode 与台账首条一致 / 同日二次变更只增 v2 不覆盖 v1 / 连续 3 tick 无变化不产新版。

> ⚠️ 这条**改变了 S-1 的旧口径**（"摘要坏了就重出"→"发出后只可补发新版"）。03 与 05 都如实登记；旧口径只在 v1.0.0-re 及更早成立。

## 六、兼容性与行为变化（升级前必读）

- **数据格式不变**：台账 `v:3`、目录布局、原文/附件/周账/月账格式均不变；升级不需要迁移。
- **行为变化**：
  1. 面板 API 守卫更严：非回环 Host / 跨源 / rebinding 形态一律 403；启用 token 后内置面板 401；
  2. 只读 GET 对"不存在/不合法 root"不再建任何目录（旧版会顺手建 `.reads`）；
  3. 日结摘要：JSON 11 键 + `.txt` 带版本、只补发不覆盖（旧版"坏了重出"被取代）；
  4. 封板 journal：`verifySealChain` 由"恒真"变为结构性校验，可能把过去"能过"的脏 journal 判为违规（这是修正，不是回归）；
  5. 单帧解压 >64 MiB 会被跳过并记 loss（旧版可能顶爆内存）。
