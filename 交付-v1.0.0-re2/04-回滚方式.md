# 04 · 回滚方式 · `v1.0.0-re2`

> 纪律：**代码可回滚，档案不可回滚。**
> 本机无 git 可执行文件 → 回滚不用 `git reset`，用**封箱快照覆盖**；发布锚以 MANIFEST + zip sha256 为准。

---

## 一、回滚目标（两个）

| 目标 | 来源 | 用途 |
|---|---|---|
| **`v1.0.0-re`**（上一版，master `a32523e` / tag `lite-v1.0.0-re`） | `<build-host>\Desktop\封箱-lite-20261113-2220\01-已完成\lite-工作树\`（不含 `.git` 时 534 文件 = 533 + MANIFEST） | 本版出问题时退回上一版 |
| **`v0.9.5-snap`**（更早的已知可用快照） | 同上封箱内的 git 历史（`.git` 只读留证；或用同版本交付 zip） | 深退 |

⚠️ **不要用"删文件重装"的方式回滚**：账库根（默认 `桌面\会话账本`）与代码包是两回事，回滚代码时**不许动账库**。

## 二、回滚步骤（Windows 资源管理器即可）

```powershell
# 0) 先停插件：插件管理器里停用（或把 profile 的 dsh.bundle 里包名移除），确认没有 tick 在跑
# 1) 备份当前包与账库（回滚不删档案，但先备份永远是对的）
Compress-Archive -Path "<当前包目录>\*" -DestinationPath "D:\回滚备份-re2-<日期>.zip"
Compress-Archive -Path "$env:USERPROFILE\Desktop\会话账本" -DestinationPath "D:\回滚备份-账库-<日期>.zip" -ErrorAction SilentlyContinue
# 2) 用上一版覆盖（保留 config/账库，不保留 re2 的代码文件）
robocopy "<build-host>\Desktop\封箱-lite-20261113-2220\01-已完成\lite-工作树" "<当前包目录>" /MIR /XD .git
# 3) 校验：上一版自带 MANIFEST 应 533/533（缺0/多0/改0）
node "<当前包目录>\证据\复现脚本\01-MANIFEST校验.mjs"
# 4) 重新启用插件，确认 tick 恢复、面板/工具可读
```

## 三、回滚对账（必须知道的兼容性）

1. **数据格式不变**：台账 `v:3`、目录布局、原文/附件/周账/月账格式三版一致 → 回滚不会读不了账。
2. **两组 re2 新增产物，旧版会"看不惯"**：
   - 日结摘要 JSON 从 10 键变 **11 键**（新增 `firstCode`）；
   - 新增 `日结摘要-YYYYMMDD.txt` / `.v2.txt`（只补发不覆盖）。
   → 回滚到 `v1.0.0-re` 后，旧版按旧口径可能把这些判为"摘要异常/需重出"（旧版 S-1 允许重出）。**处置**：回滚后让旧版重出一次摘要即可，不影响台账与原文。若不想有任何扰动，先只回滚代码、**暂停收据锚（`receiptAnchorRoot` 置空）**，观察一轮再决定。
3. **封板 journal**：re2 提高了校验严格度（结构性违规会报红）；回滚到旧版会回到"恒真"，历史 journal **不需要改**。
4. **面板 API**：re2 的守卫更严（非回环 Host 403、token 可选）。回滚后守卫回到旧版（更松）。若你之前设置了 `DSH_DIALOG_LEDGER_PANEL_TOKEN`，回滚后该变量被忽略，记得清掉以免混淆。

## 五、什么情况**不要**回滚

- 账库本身有问题（坏帧/未闭合轮/摘要过期）：那是数据面，升级不会修数据，回滚也不会；
- 只是面板/工具报错：先看 05 与 README 的已知边界，回滚是最后手段；
- 已经用 re2 发过日结摘要给别人：回滚会让"补发新版"的版本号断档，**先补发一次再回滚**（或保留 re2 只停用 token）。
